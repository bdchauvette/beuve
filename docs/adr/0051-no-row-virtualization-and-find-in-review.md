# 0051. No row virtualization inside cards, and "Find in review" over the review data

- Status: Accepted
- Date: 2026-10-30

## Context

A diff card renders every row of its patch (ADR 0025). The profiling behind ADR 0050 showed what that costs for a giant file: a 20 000-line added file is 248 000 DOM nodes, its first highlight is a 6 s main-thread task, and scrolling past it runs at 80–180 ms a frame. `@pierre/diffs` ships `VirtualizedFileDiff` and a `Virtualizer` that keep only the rows near the viewport in the DOM, and a prototype on the existing `.body`/`.cards` scroll container cut that file to 4 600 nodes with 33 ms worst frames. ADR 0025 had rejected the `Virtualizer` for the whole stream; the question was whether to use it inside giant cards.

Many interactions assume that every row of a card is in the DOM. We checked each one against the prototype (the `exp` branch, `VirtualizedFileDiff` with a shared `Virtualizer` and the worker pool), on a 20 000-line file with 150 hunks whose patch is 1 455 lines, in Electron 45 under Xvfb:

| Interaction                                                                                                           | Whole card (today)                                                                           | Virtualized card                                                                                                |
| --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Rows in the DOM                                                                                                       | 2 200                                                                                        | 183                                                                                                             |
| Jump to a far head line (`revealLine`: citations, URA "show", palette, peek/flow/trace lines, `o`'s target, composer) | row found, scrolled 30 519 px                                                                | row never rendered, `waitFor` gave up after 480 ms, scrolled 12 px                                              |
| `j`/`k` to the last hunk (`revealHunk`)                                                                               | scrolled to it                                                                               | did not move (12 px)                                                                                            |
| Select all / copy across the card                                                                                     | 1 922 lines                                                                                  | 159 lines (the window only)                                                                                     |
| Screen readers                                                                                                        | every row                                                                                    | only the 183 rows in the DOM                                                                                    |
| Insight, URA marker and composer annotations; peek/flow/trace portals                                                 | rendered with their rows                                                                     | rendered only while their row is in the window, so `revealInsight` and `waitForComposer` find nothing offscreen |
| Hunk expansion, split/inline switch, scroll restoration                                                               | positions from the DOM                                                                       | depend on measured virtual heights                                                                              |
| Browser find                                                                                                          | Electron has no find bar; `window.find` misses text inside the diff's shadow root either way | same                                                                                                            |

The library has no line-to-offset API (`isLineRenderable` and `getNumericScrollAnchor` go the other way), so making jumps work means computing row offsets ourselves from hunks, separators, expanded regions and annotation heights, and keeping that in step with the library's layout. Copying and screen-reader access across a card can't be fixed at all while offscreen rows are absent. beuve had no find feature: no `webContents.findInPage` wiring, no ⌘F.

## Decision

- **No virtualization inside cards.** Not every interaction above can be made to work (copy and accessibility can't), so we keep whole cards and handle giant ones with ADR 0050 and 0052 instead: workers keep highlighting off the main thread, and a diff over 3 000 lines or 256 KiB of patch text starts collapsed behind "Load diff". Loading one renders the whole card, slow but complete. ADR 0025's lazy near/far mounting of whole cards is unchanged.
- **Find in review** (⌘F / Ctrl+F anywhere, and in the palette through the command registry). `find-in-review.ts` (pure) searches the review data, every file's patch text, not the DOM: context, added and deleted lines with their head or base line numbers, case-insensitive unless Aa (Alt+C) is on, at most 5 000 hits. `beuve-find-bar` sits above the stream; typing jumps to the first hit at or after the active file, Enter and Shift+Enter (or ↓/↑, F3) step, Escape closes and returns focus to the diff. Each hit is revealed through the same jump citations use (`revealRange`): a collapsed card loads first, then the line is selected and scrolled into view. Collapsed, unmounted and offscreen cards are found the same way. We chose this over `webContents.findInPage`, which only sees mounted text and cannot open a collapsed card.

## Consequences

Every jump, selection, copy and screen reader keeps working on every card. A giant file costs nothing until the reviewer loads it, and then costs what it did before ADR 0050 minus the highlighting, which runs in workers. Find highlights the hit's line, not the matched characters, and searches only what the patch shows (expanded context is not searched). If upstream adds a line-to-offset API and accessible offscreen rows, virtualizing giant cards can be reconsidered; the find bar and the jump path would not change.
