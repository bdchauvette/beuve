# 0145. Emoji shortcode completion in note fields

- Status: Accepted; amends [0127](0127-chat-command-completion-and-message-navigation.md) (its completion pieces are shared)
- Date: 2026-11-18

## Context

Reviewers asked for a shortcode emoji picker where they write notes. Notes already render `:tada:` through the rendered Markdown view's emoji table (ADR 0123), but GitHub and the exports carry the text as written, and remembering exact names is the hard part. The chat input already has a completion list (ADR 0127) with a pure key planner, list styles and the `listbox` + `aria-activedescendant` pattern; the note fields are plain `<input>` and `<textarea>` elements in the composer's and the notes list's shadow roots, which own Escape (cancel) and ⌘/Ctrl+Enter (save).

## Decision

- **Where.** The note composer's title and body, the notes list's inline editor title and body, and the notes list's GitHub review summary. The chat input is left out: it is a contenteditable with mention chips and its own `/` completion, and mixing the two lists there is not trivial.
- **What opens it** (`findEmojiQuery`): a `:` at the start or after anything but a letter, digit, `_` or another `:`, then two or more of `a`–`z`, digits, `_`, `+` and `-`, just before a collapsed caret. So `10:30`, `https://` and a closed `:tada:` never open it. Case is ignored.
- **What it lists** (`matchEmojiShortcodes`): the `full` table of `markdown-it-emoji` (ADR 0123, imported as `markdown-it-emoji/lib/data/full.mjs`, which the renderer bundles already; no new dependency), so what completes is what renders. Exact name, then prefixes, then a later word's prefix (after `_`), then any substring; shorter names first within each, then the table's order. An emoji with several names shows once, under its best name. At most eight; a linear scan of the 1,903 names per keystroke.
- **Keys** (`planCompletion`, catalog entry `emoji-complete` for the shortcuts window): ↓ ↑ move, Enter and Tab insert, Escape closes the list until the `:name` starts somewhere else. The first row is always highlighted, so Enter inserts rather than starting a line or saving while the list is open. A closing `:` after an exact name (`planClosingColon`) inserts its emoji whether or not the list is open. Keys the list takes are handled in the capture phase on the host's shadow root and stopped there, so Escape closes only the list, not the composer or editor. With the list closed, and for every modified key (⌘/Ctrl+Enter saves), the host's own handling is unchanged.
- **Inserting.** The emoji character replaces the typed `:name` (never the shortcode text): the controller selects `:name` and runs `document.execCommand('insertText')`, which keeps Chromium's undo stack (⌘/Ctrl+Z gives the `:name` back) and fires `input` as typing does, so the hosts' state updates as before. If that fails it falls back to `setRangeText` and fires `input` itself, losing only undo. Read-only and disabled fields are left alone.
- **One controller** (`EmojiCompletion`, a Lit `ReactiveController`): the host creates it as a field, marks each field with `data-emoji-completion` and the pattern's static ARIA, and renders its list once in its shadow root, so ids resolve for `aria-activedescendant`. The list is a `popover="manual"` `listbox` shown with `showPopover({ source: field })` and placed by CSS anchor positioning under the field (flipped above when there is no room). It sits in the top layer, so the notes list's scrolling never clips it. It is anchored to the field, not the caret: the note fields are a few lines high, and measuring caret positions in a textarea needs a mirror element.
- **ARIA.** An `<input>` is `role="combobox"` with `aria-expanded`. A `<textarea>` keeps its implicit `textbox` role, because ARIA in HTML permits no other role on it, and `textbox` does not take `aria-expanded`. Both carry `aria-autocomplete="list"`, `aria-controls` and, while the list is open, `aria-activedescendant` on the highlighted option.
- **Shared pieces (amending ADR 0127).** `planChatCompletion` becomes `planCompletion` (`plan-completion.ts`), unchanged in behavior. The list's surface and row styles move from `chatCompletionStyles` to `completionListStyles` (`.completion-list`, `.completion`), which the chat drawer and the emoji list both use. `chatCompletionStyles` keeps only where the chat's list sits and its two columns.

## Consequences

Emoji are a keystroke away in every note field, and what the list offers is exactly what the rendered view renders. A new text field gets completion by carrying the marker and the ARIA attributes in a host that has the controller. Enter inserts while the list is open, which is one more keystroke for a reviewer who wanted a new line after `:ok`, and Escape then reopens nothing until the name starts over. The undo path depends on `execCommand`, which is deprecated but is still the only way to edit a field undoably.

## Amendment 2026-11-18: the list follows the caret

Under the whole field, the list sat far from where the reviewer was typing in a long body. It now sits just below the line the `:name` starts on, at its `:`, so it holds still while the name is typed. It flips above that line when there is no room below and stays inside the window (`placeHoverCard`, the hover card's placement). `caretRectFrom` measures the `:` with `dom-input-range` (ADR 0147). CSS anchor positioning is gone: the controller sets the popover's `inset-inline-start` and `inset-block-start` itself (the renderer is horizontal and left to right, as the hover card assumes). It places the list again on every change the list shows, on scrolling in the host's shadow root or the window, and on resize, while the list is open. Keys, insertion and ARIA are unchanged.
