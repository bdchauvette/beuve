# 0029. The flow graph channel, its portal, and the persisted reviewer verdict

- Status: Accepted
- Date: 2026-10-28

## Context

ADR 0028 built control-flow graphs and a layout but nothing reached them. Separately, ADR 0027 left the reviewer's chosen verdict in the dock only, so `beuve_read_human_review` always reported the derived verdict and an agent never saw what the reviewer decided.

## Decision

- **`flow:get-graph { sessionId, path, line }`** (1-based head line, like `lsp:call-hierarchy`) answers `IpcResult<FlowGraphResponse>`: `{ kind: 'graph', graph }` or `{ kind: 'failed', failure, message }` with `failure` one of `unsupported-language`, `no-function-at-line`, `too-large` and `file-unavailable` (deleted, binary, submodule, unreadable or too big to parse). Expected outcomes are values, not `IpcError`s, so the UI can say what is wrong; unknown sessions or paths outside the review are `not-found`, a parser that cannot load is `internal`. The DTOs mirror the flow domain's data, since `src/contract` cannot import domains.
- **Main** (`src/main/flow/`) finds the file in the review the session shows now, reads the head blob by its id from the diff (`readBlobs`), parses it with the syntax domain, takes `findFunctionAt` with the language's flow rules and builds the graph with the head lines the review changed: added lines, and the two lines around a pure deletion, but an edit marks only its new lines. Graphs are cached per (head blob, base blob, function start line) in an LRU of 64, because the blob pair fixes the changed lines; a second LRU remembers which function a requested line fell in, so a repeat request skips the blob read and the parse. Failures are not cached.
- **`Shift+p`** targets the first changed head line of the focused hunk, else of the file; `p` now does the same (`findFirstChangedLine(patch, hunkIndex)`). The graph opens in the card's inline portal area (`beuve-flow-portal` hosting `beuve-flow-graph`), where the peek also lives; opening one closes the other, so there is one portal at a time. Focus moves into the graph, the arrow keys walk the flow, Enter fires `flow-node-activate` and the card scrolls to that line, and Escape closes either portal and returns focus to the diff stream.
- **Layout fixes found by looking** at real graphs: a back edge (`continue`, `loop-back`) now leaves and enters through the side of a node only when nothing sits right of it in its row, and otherwise runs through the gaps between rows (bottom exit, top entry) so it never crosses a node. Edge labels sit beside the first horizontal run, on the side the run heads to, with a background-coloured halo.
- **Chosen verdict** is stored per session in `ura_verdict_choices` (migration `ura-0002-verdict-choices`; session id, the verdict or a cleared reason, timestamp; deleted with the session). `ura:set-verdict { sessionId, verdict? }` sets it; omitting the verdict, or passing the derived one, removes it (choosing the derived value is no choice, as in ADR 0027). `ura:list` carries `chosenVerdict` and `verdictNotice`; `ura:export` and `beuve_read_human_review` use the stored choice, and an explicit `verdict` on `ura:export` still overrides it for that export only.
- **A choice that becomes impossible is cleared, and the reviewer is told.** Approve cannot stand while a blocker is staged. `settleVerdictChoice` runs after every item change from any caller (it is part of the change announcement) and on every read, so no reader sees approve over a blocker; it replaces the choice with a remembered reason `blocker-staged`, and `ura:list` reports "Your Approve verdict was cleared because a blocker is staged. The derived verdict applies." until the reviewer chooses again. Setting approve while a blocker is staged is `refused`.

## Consequences

The graph costs one blob read and one parse the first time a function is asked for, and a map lookup afterwards. Pure renames (no blob ids in the diff) have no graph. The `p` peek now follows the focused hunk instead of always the file's first change. An agent reads the reviewer's decision over MCP, but a verdict is advisory until the reviewer exports: it is not tied to a head, so a new commit keeps it (a blocker added later clears an approval, nothing else does). `ura:set-verdict` is a new write path every caller must go through; the dock no longer keeps its own copy.
