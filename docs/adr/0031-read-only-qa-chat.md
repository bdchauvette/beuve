# 0031. Read-only Q&A chat: messages, citation grammar, context budget and privacy

- Status: Accepted (mentions added by [0046](0046-chat-context-mentions.md), summaries by [0047](0047-chat-compaction.md))
- Date: 2026-10-28

## Context

Zone 4 (spec 4) is a read-only Q&A drawer. Answers carry citation pills that jump the diff stream to the code they rely on. ADR 0022 made the drawer the place where `/review` starts and left plain text for Q&A. The model must explain, query and audit, and never author (spec 1). Each question costs the user's Claude Code quota and sends code to Anthropic.

## Decision

- **Domain** `src/internal/chat/`, pure apart from the model port (ADR 0030). `askQuestion(input, { model, signal?, onDelta?, onProgress?, budget?, timeoutMs? })` gives `Result<ChatAnswer, ChatError<E>>`. `ChatAnswer` is `{ answer, citations, dropped, malformedCitations, prompt, usage }`. `ChatError` is `empty-question`, `question-too-long` (over 8000 characters, refused rather than truncated) or `model` with the adapter's error, cancellation included. The timeout defaults to 5 minutes. The model runs in the head worktree with Read, Grep and Glob only, and the prompt says it may look beyond the diff.
- **Prompt** (`buildChatPrompt`, deterministic). The system prompt says to explain and audit only, never to offer to edit or claim to have edited, and to show changes as prose or a fenced `diff` the reviewer can stage. It treats the diff, the repository, ImpactGate findings and earlier answers as untrusted data and states the citation grammar. The user prompt holds the change range, up to 20 ImpactGate findings, the diff (200k characters in total, 40k per file; a file that doesn't fit keeps its leading hunks, and omitted hunks and files are named, with a pointer to Read them), the earlier turns, the reviewer's focus (path, lines and up to 8k characters of hunk text) and the question, last. Turns are bounded to 20 and 40k characters, with 10k per turn. The oldest are dropped first, and the prompt says how many. `toChatHistory` keeps questions and completed answers only. Untrusted text is fenced so it can't close its fence.
- **Citation grammar**: `[[path:line]]` or `[[path:start-end]]`, on one line, with a repository-relative path, the last colon separating the lines, and 1-based, inclusive head-side lines (`start <= end`). `parseCitations` finds the markers and counts the malformed `[[…]]` spans. `validateCitations` checks each path against a set: the diff's non-deleted head paths plus `worktreePaths`, which main fills from the head tree (e.g. `git ls-files`). It makes absolute paths inside the worktree relative and rewrites kept markers to the canonical `[[path:start-end]]`. Unknown paths become inline code and are reported as `dropped`. Citations are deduplicated, in order of first appearance, with `side: 'head'`. Line numbers aren't checked against file lengths. The UI renders a pill for each occurrence of exactly `[[${path}:${startLine}-${endLine}]]` for a citation in the message's `citations`, and shows anything else as text.
- **Messages** (`chat-0001-messages`, `chatMigrations`): `chat_messages(id, session_id → sessions ON DELETE CASCADE, head_sha, role user|assistant|system-notice, content, citations JSON array, status streaming|complete|failed|cancelled, error_code, created_at)`, STRICT, with CHECKs: only assistants have a status other than `complete`, `error_code` is set exactly when the status is `failed`, and a question is never blank. Repository functions: `appendChatMessage`, `updateChatAnswer` (streaming preview, then final content, citations and status), `listChatMessages` (by `created_at`, then insertion), `clearChatMessages`. `ChatMessage` is a union, so a `failed` answer always has an `errorCode`.
- **Main's recipe**: `chat:ask { sessionId, question, focus? }` stores the user message and a `streaming` assistant message, then answers at once with both ids. One question can be in flight per session. Main builds the input from the same diff as `session:get-review`, the cached ImpactGate findings, the head checkout (ADR 0020) and the stored history. It pushes `chat:delta { messageId, append | reset }`, throttles writes of the preview, then stores `complete`, `failed` (with the code from `ModelError`) or `cancelled`. `chat:cancel` and a head move abort the question. `chat:list` and `chat:clear` wrap the repository. In the drawer, plain text becomes a question, while `/review` and `/help` keep working.

## Consequences

- **Privacy**: nothing is sent until the reviewer asks a question. Each question sends the question, the bounded diff, ImpactGate findings, the focus, earlier turns and any worktree file Claude Code reads (`--restricted` keeps reads in the checkout) to Anthropic, through the user's own Claude Code account and under its terms and data settings. beuve never sees a credential and doesn't log prompts or answers. The drawer should say this, as it does for `/review`.
- History is resent with every question, since each question is a fresh `claude --print` process. That is simple and stateless, but long conversations cost more context.
- Spec 4 indexes the chat on embeddings and LSP symbols. This version reads files through tools instead, so there is no index to build or keep fresh, and large repositories answer more slowly.
- Streamed text shows raw, unvalidated markers until the final answer replaces it.
