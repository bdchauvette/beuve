# 0058. Tests use fixtures, run concurrently, and take `expect` from their context

- Status: Accepted; amends [0013](0013-test-helpers-in-testing-directories.md)
- Date: 2026-10-30

## Context

About 1,350 tests share setup through `beforeEach`/`afterEach`, module-level `let`/`const`, a stepping clock in `*Deps`, and one `vi.mock`. That state forces tests within a file to run one at a time, hides what each test depends on, and makes isolation the default cost: every file gets its own worker (≈300 workers at ≈120 ms each). Most integration tests spawn real `git`, language servers or fake CLIs, so setup cost is dominated by processes and the file system, not JavaScript.

Measurements on the 4-core Linux container (ext4, git 2.43, Node 26.13):

| Way to get a fresh repository for a test              | empty repo | 8 commits      |
| ----------------------------------------------------- | ---------- | -------------- |
| `git init` + 4× `git config` (+ commits), per test    | 24.3 ms    | 154.8 ms       |
| `fs.cpSync` of a template, recursive                  | 1.8 ms     | 9.8 ms         |
| `fs.cpSync` with `COPYFILE_FICLONE`                   | 1.7 ms     | 11.7 ms        |
| `cp -R --reflink=auto` (a child process)              | 6.0 ms     | 18.8 ms        |
| `git clone --local` (hard-links objects) / `--shared` | –          | 31.8 / 30.7 ms |

ext4 has no reflinks, so `COPYFILE_FICLONE` falls back to a copy here; on APFS (macOS CI and laptops) libuv's `COPYFILE_FICLONE` uses `clonefile`, and Btrfs/XFS use `FICLONE`. A clone also rewrites `origin` and the refs layout, so it is not an exact copy.

Node 24 has no virtual file system; Node 26 has `node:vfs` behind `--experimental-vfs`. A mounted VFS is visible only inside the process: a file written to it reads back with `fs.readFileSync`, but `cat` on the same path fails (`/dev/null/vfs/1/a.txt: Not a directory`), because mounts live under a fake prefix in Node's `fs` layer. Since the tests that need isolation are the ones that spawn `git` and servers, a VFS would help none of them. In-memory SQLite (`openDatabase(':memory:')`) already gives each test its own database at no cost.

`@vitest/eslint-plugin` 1.6.28 (2026-10-22; peer `eslint >=8.57`, `vitest *`, `typescript >=6`) runs on ESLint 10 and Vitest 5. It has no rule requiring `expect` from the test context, none against module-scope state in tests, none tying fake timers to sequential tests, and `no-restricted-vi-methods` cannot tell `vi.spyOn(localObject)` from `vi.spyOn(importedModule)`.

## Decision

- **Fixtures, not hooks.** Tests import `test` from the nearest `testing/test.ts`, a chain of `test.extend` fixtures, and destructure what they need: `test('…', async ({ expect, repo, repository }) => …)`. Setup and teardown live in fixtures (`onCleanup`); `beforeEach`/`afterEach`/`beforeAll`/`afterAll`/`around*` and `onTestFinished`/`onTestFailed` imports are banned in converted tests.
  - `#testing/test.ts` (new `src/testing/`, domain-free): `tempRoot` (worker), `tempDir`, `db` (empty in-memory SQLite), `logger` (records lines), `clock` (fakes `Temporal.Now` and `Date`, ADR 0059).
  - `#internal/git/testing/test.ts`: `repositoryTemplates` (worker), `repositories` (`create()`, `fromTemplate(template)`), `repo`, `repository` (a `GitRepository` on `repo`).
  - A domain's `testing/test.ts` extends the nearest layer below and may re-extend a fixture with its parent's value, e.g. the session domain's `db` runs the session migrations on `#testing/test.ts`'s `db`.
  - Fixtures for other layers (fake `claude`, fake `gh`, the fake GitHub API, `src/main` services) are added to the owning domain's or layer's `testing/test.ts` as those directories are converted; they wrap the existing helpers (`writeFakeClaude`, `writeFakeGh`, `createFakeGithubApi`). Servers listen on port 0, so ports never collide.
- **Repository templates.** A `RepositoryTemplate<T>` (`{ name, build(repo): T }`) is built once per worker under `tempRoot` and copied into each test with `fs.cpSync(…, { recursive: true, mode: COPYFILE_FICLONE })`. `build` returns plain data (shas), which every copy shares. Even an empty repository comes from a template. Domain isolation still applies: `src/main` may use `#internal/git/testing/*`; other domains build repositories with their own helpers.
- **No module-scope bindings in tests** (`local/no-module-scope-bindings`): no top-level `const`, `let` or `var`. Imports, types and top-level `function` declarations are allowed: with no module bindings there is nothing for a function to share, so small builders such as `function session(): Session` stay next to the tests. Anything used by several files goes to `testing/`.
- **`expect` from the context** (`local/expect-from-test-context`): never imported, never global, always a parameter (the test's or a helper's that receives it), so concurrent tests count their own assertions.
- **Concurrent by default.** Converted directories run in the Vitest project `concurrent` with `sequence.concurrent: true` and `isolate: false` (files share workers; worker fixtures such as templates are reused across files). A test opts out with `test('…', { concurrent: false }, …)` (Vitest 5 has no `test.sequential`); it then runs alone, between the concurrent groups before and after it. A test must opt out when it fakes time or touches process-wide state such as `process.env`. `local/require-sequential-fake-time` reports a `vi.useFakeTimers`/`vi.setSystemTime` call, or a `clock` fixture, in a test without `{ concurrent: false }` (on the test or an enclosing `describe`), and any fake-time call outside a test.
- **No module mocking.** `vi.mock`, `doMock`, `unmock`, `doUnmock`, `hoisted`, `importActual`, `importMock`, `resetModules`, `stubGlobal` and `stubEnv` are banned through the plugin's `no-restricted-vi-methods`; `local/no-module-mocking` adds what the plugin misses: `vi.spyOn` on an imported binding or a member of one, computed `vi['mock']`, and the `vitest.` alias. Dependencies are injected instead. Clocks are the exception: they are not injected (ADR 0059).
- **Narrowing results without `if`.** `okValueFrom(result)` (`#testing/ok-value-from.ts`) returns an `ok` value or throws; tests assert a `Result` itself when the result is what they check.
- **`@vitest/eslint-plugin` 1.6.28** is a new devDependency. Converted tests get its `recommended` rules plus `consistent-test-it` (`test` everywhere), `consistent-vitest-vi`, `hoisted-apis-on-top`, `max-nested-describe` (2), `no-alias-methods`, `no-commented-out-tests`, `no-conditional-expect`, `no-conditional-in-test`, `no-conditional-tests`, `no-disabled-tests`, `no-duplicate-hooks`, `no-focused-tests`, `no-hooks`, `no-mocks-import`, `no-restricted-vi-methods`, `no-standalone-expect`, `no-test-prefixes`, `no-test-return-statement`, `no-unneeded-async-expect-function`, `prefer-comparison-matcher`, `prefer-each`, `prefer-equality-matcher`, `prefer-expect-resolves`, `prefer-mock-promise-shorthand`, `prefer-spy-on`, `prefer-strict-equal`, `prefer-to-be`, `prefer-to-be-object`, `prefer-to-contain`, `prefer-to-have-length`, `prefer-todo`, `prefer-vi-mocked`, `require-awaited-expect-poll`, `require-local-test-context-for-concurrent-snapshots`, `require-to-throw-message`, `valid-expect-in-promise` and `valid-title`. The setting `vitest.vitestImports` makes the plugin treat `test` from any `testing/test.ts` as Vitest's. Left off: `require-top-level-describe` (a flat file of `test('fn does x')` reads fine; `describe` stays optional), `prefer-importing-vitest-globals` (it accepts only imports from `vitest` itself), `no-done-callback` (deprecated; it mistakes the destructured context for a `done` callback), `prefer-lowercase-title` (titles start with function and product names), `prefer-expect-assertions` and the `padding-*` rules (Prettier formats). `e18e/prefer-static-regex` is off in converted tests, which cannot hoist regexes to module scope.
- **`src/ui/testing/test.ts`** is the renderer's own `test`: `src/ui` typechecks with DOM libraries and no Node types, so it cannot extend `#testing/test.ts` (which uses `node:*`). It extends `vitest` directly and holds DOM-safe fixtures (`colorsOf`, Shiki through the light TextMate theme). `src/ui/testing/` may therefore use vitest and `@pierre/*` (`no-dev-deps-in-src`, `pierre-only-in-wrappers`).
- **Migration.** `converted-test-dirs.ts` lists the converted directories (the `*.test.ts` directly inside each). `eslint.config.js` applies the rules above, and `vitest.config.ts` the `concurrent` project, to exactly those files; the rest run in the `legacy` project as before. A directory joins the list in the commit that converts it. When the list covers everything, the `legacy` project and the list go away.
- `src/testing/` is a shared leaf like `src/x` (`shared-testing-is-leaf`: Node built-ins, vitest, `src/x`, `src/sqlite` and itself). It may use vitest, a devDependency; `testing-only-in-tests` keeps it, like every `testing/` directory, out of bundles.

## Amendment: test helpers never block the worker

A test's timeout starts when its test starts. Tests in a file run concurrently in one worker thread, so a synchronous call (`execFileSync`, `execSync`, `spawnSync`) blocks every other test in that file: the tests run one after another while all their timers tick, and each test's 5 s limit ends up covering the whole file's work. On the 3-vCPU macOS runner, three tests of `find-stack-fork-point.test.ts` timed out at 5.0 s (the others finished at 1.7–3.7 s, the file at 6.9 s), though each takes about 0.4–1.4 s alone. Pinning the worker to 3 CPUs next to 3 CPU-burners reproduced it in 3 of 4 runs.

- `TestRepository.git` and `commit` are async (`execFile`, no shell) and resolve to the same values; `RepositoryTemplate.build`, `repositories.create`, `repositories.fromTemplate` and the `repo` fixture return promises. The template cache stores the build promise, so concurrent tests share one build.
- `no-restricted-imports` bans `execFileSync`, `execSync` and `spawnSync` in converted test files and in `testing/` directories.
- Async alone was not enough: with 3 CPUs and 3 CPU-burners, 4 of 8 tests in the file still timed out at 5 s, because the work is CPU-bound git and every concurrent test's timer covers all the others' work. The `concurrent` project therefore sets `maxConcurrency` to half of `os.availableParallelism()` (at least 1): 1 on a 3-vCPU runner, 2 on this 4-core container. With it, 6 of 6 runs of `src/internal/git` passed under that load. `testTimeout` stays at 5 s.

## Consequences

Each test lists its dependencies in its signature, and shared fixtures replace copy-pasted `beforeEach` blocks. The converted directories (`eslint-local-rules`, `src/internal/git`, `src/internal/session`: 327 tests) went from 9.3–10.5 s to 4.9–5.5 s wall time, mostly from `isolate: false`; within-file concurrency alone gained little on 4 cores, because files already run in parallel workers and git is CPU-bound (`maxConcurrency` 1, 5 and 10 all measured 7.2–7.7 s for git and session). The whole suite went from 45.6–46.5 s to 39.5–43.1 s with 82 more tests. Templates make repositories with history nearly free, so tests can afford realistic histories. Tests that fake time or set `process.env` run one at a time. Two partly converted layouts coexist until every directory is in `converted-test-dirs.ts`. A VFS is not an option while tests spawn processes.
