# 0069. A second model adapter: the Claude Agent SDK with the user's API key

- Status: Accepted; adds an adapter to the port of [0019](0019-review-model-port-and-claude-code-cli-adapter.md) and [0030](0030-llm-domain-and-structural-model-ports.md)
- Date: 2026-10-30

## Context

The only adapter drives the user's installed `claude` CLI with their own Claude Code login (ADR 0019). Users without Claude Code, or who want reviews billed to an organization's Console account, need an adapter that authenticates with an Anthropic API key. Two ways were weighed: the client SDK (`@anthropic-ai/sdk`) with our own `read_file`/`grep`/`glob` tools and sandbox, or the Claude Agent SDK, which runs Claude Code's own harness. A client-SDK sandbox means owning path confinement, symlink handling, size caps and a regular-expression engine that a model-written pattern can't hang (catastrophic backtracking in main's event loop), and it drifts from what the CLI adapter's model sees. The Agent SDK reuses the exact harness, tools and permission engine of ADR 0019, and the SDK docs allow API-key authentication for third-party products while forbidding them to offer claude.ai login.

## Decision

- **Dependency**: `@anthropic-ai/claude-agent-sdk` pinned at `0.3.312`, which bundles Claude Code 2.1.312 (the version ADR 0019's flags were checked against) as a per-platform native binary in an optional dependency (`@anthropic-ai/claude-agent-sdk-<platform>-<arch>`, about 280 MB unpacked). npm installs its peer `@anthropic-ai/sdk`; beuve's code does not import it.
- **Adapter** `createAgentSdkModel(options)` (`src/internal/llm/create-agent-sdk-model.ts`) implements `LanguageModel` unchanged, so chat, `/review`, `/summarize` and `/compact` can use either adapter. Each run is one `query()`. Its stream-json messages are the CLI's, so both adapters read them with `claudeCodeEventFrom` and map outcomes with `classifyClaudeCodeOutcome`: same `ModelError`s, same `append`/`reset` text preview, same `started`/`tool-use` progress. `run` sends the zod schema's JSON Schema as `outputFormat` (Claude Code's `StructuredOutput` tool) and validates the answer with zod (`invalid-output` otherwise).
- **Defaults**: model `claude-opus-5-5`; effort `high` (Claude Opus 5.5 defaults to `medium`, and review is intelligence-sensitive work; `/review --effort` and the options override it); adaptive thinking (Claude Code's default; Opus 5.5 can't disable thinking); streaming always (Claude Code streams every request); at most 100 turns; `maxBudgetUsd` optional.
- **Read-only configuration**, every option and flag checked against the 0.3.312 types or `claude --help` for 2.1.312: `tools` and `allowedTools` = `Read`, `Grep`, `Glob`; `disallowedTools` = `Bash`, `Edit`, `Write`, `NotebookEdit`, `WebFetch`, `WebSearch`; `permissionMode: 'dontAsk'` with `permissionPrompts: 'none'` (anything not pre-approved is denied, nobody is asked); `settingSources: []`, `strictMcpConfig` with no servers, no plugins, `persistSession: false`; `cwd` = the worktree; the Claude Code system prompt with the request's `system` appended; and, through `extraArgs`, `--safe-mode` (no CLAUDE.md, skills, plugins, hooks, MCP from the worktree or the machine), `--restricted` (no code-running tools, file tools confined to the working directory) and `--disable-slash-commands`. A `title` is set so Claude Code makes no extra request to name the session. Tests confirm reads outside the worktree are denied directly, through `..` and through a symlink, and that `Write` and `Bash` don't exist. `--bare` was rejected: it would force API-key auth but drops `Grep` and `Glob`.
- **Credentials**: main passes the key as `apiKey`; the adapter puts it in Claude Code's environment as `ANTHROPIC_API_KEY` and never logs it. The environment is ADR 0019's allow-list plus that key, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, `DISABLE_AUTOUPDATER=1`, `CLAUDE_AGENT_SDK_CLIENT_APP=beuve`, and optionally `ANTHROPIC_BASE_URL` and `CLAUDE_CODE_MAX_RETRIES`; an inherited `ANTHROPIC_BASE_URL` or token is dropped, so the key can't be redirected. Each run gets a fresh private `CLAUDE_CONFIG_DIR`, removed afterwards, so the user's Claude Code login, settings, history and memory are never read. If Claude Code's init event reports any credential source but `ANTHROPIC_API_KEY`, the run is stopped as `not-authenticated`. A blank key is `not-authenticated` before anything starts. There is no claude.ai login path.
- **Key handling contract for main** (later step): read the key from `safeStorage`-encrypted storage, never from the renderer; the Settings UI sends a new key write-only over IPC and gets back only "set / not set"; the key never crosses to the renderer, logs or the database in clear; main constructs the adapter per request with it.
- **Refusals**: Claude Code handles them. On `stop_reason: "refusal"` it first continues once with a note, then retries the turn on its per-category fallback model (`claude-opus-4-8` for Opus 5.5 in 2.1.312), with the fallback-credit beta; the adapter reads the `model_refusal_fallback` message, reports the fallback as `model`, and the preview resets because a new message starts. A refusal Claude Code doesn't recover from ends as `model-failed`. The client SDK's server-side `fallbacks` parameter is not used: Claude Code owns the request.
- **Errors**: 401/403 → `not-authenticated`; 429/529 → `rate-limited` (`resetsAt` only when Claude Code reports a rate-limit event; Claude Code itself honours `retry-after` when it retries); timeout (a `Temporal.Duration`, enforced with the SDK's `AbortController`) → `timeout`; the request's `AbortSignal` → `cancelled`; a missing binary → `not-installed`; a crash before a result → `process-failed`; other failed results → `model-failed`, now with the HTTP `status` when one caused it. `ModelOutput` gains optional `usage` (input, output and cache tokens) for both adapters.
- **Packaging**: main is an esbuild bundle without `node_modules`, so the SDK can't find its binary there; main must pass `pathToClaudeCodeExecutable`. `electron-builder.yml` needs a `files` entry copying `node_modules/@anthropic-ai/claude-agent-sdk-darwin-arm64` (filter `claude`, `package.json`, `LICENSE.md`; `-linux-x64` for Linux builds) and the same path in `asarUnpack`, because a binary inside `app.asar` can't be executed; main resolves it at `process.resourcesPath/app.asar.unpacked/node_modules/@anthropic-ai/claude-agent-sdk-${platform}-${arch}/claude`. It is a native executable, not run with `ELECTRON_RUN_AS_NODE`. electron-builder signs it with the app; whether the hardened runtime needs more than `allow-jit` for it must be checked on the first signed build. A bundled run under Electron's Node 24 was verified with an explicit path.
- **Tests** never call the real API: they run the real bundled Claude Code against a local fake Messages API (`testing/start-fake-messages-api.ts`, server-sent events in the API's streaming shape, scripted replies, every request recorded) through `ANTHROPIC_BASE_URL`, with `CLAUDE_CODE_MAX_RETRIES=0`. They cover streaming, a `Read` + `Grep` round trip, escapes, write attempts, structured output, a schema failure, the refusal fallback, 401, 429, a missing key, a missing binary, timeout and abort. A fake executable was rejected: the SDK talks to Claude Code over an undocumented control protocol on stdin. The tests run one at a time; each starts a Claude Code process.

## Consequences

- One harness for both adapters: a Claude Code upgrade means bumping the SDK pin and re-checking the flags above, and the fake API must keep up with what Claude Code sends.
- Cost: every request is billed to the key's Console account at API rates (Claude Opus 5.5: $4 / $20 per million input / output tokens, cache reads $0.20), with no subscription limits. A `/review` reads many files across many turns, so its prompt grows each turn; Claude Code's prompt caching keeps the repeated prefix cheap, and `effort`, `maxTurns` and `maxBudgetUsd` bound a run. `ModelOutput.costUsd` is Claude Code's estimate and `usage` the token counts, for main to show.
- The app grows by the platform binary (about 280 MB on disk, less compressed).
- Privacy is as in ADR 0019, but under the key owner's API terms and data settings instead of the user's Claude Code account.
