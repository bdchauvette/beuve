# 0046. Chat context mentions: grammar, resolution at the commit, budget priority and persistence

- Status: Accepted; amends [0031](0031-read-only-qa-chat.md) and [0032](0032-chat-wiring-one-answer-per-session.md)
- Date: 2026-10-29

## Context

Reviewers want to point the chat at exact lines, as Zed's "add selection to thread" does, instead of hoping the focus (the file under the cursor, ADR 0032) and the diff are enough. The selection can be on either side of a split diff, a staged note, or a whole file from the tree or the palette. What the model sees must be the text the reviewer saw, not whatever the worktree holds, and a few large selections must not crowd out the rest of the prompt or grow it without bound.

## Decision

- **Adding.** ⌘> / Ctrl+> (Shift+Period, Zed's binding; nothing in beuve or Electron's default menu uses it) runs `add-to-chat` from the command registry (ADR 0044), also in the palette. The source follows the focused region: in the diff, the card's line selection (`base` when both ends are on the deleted side: a split view's left column, or deleted rows inline), else the focused hunk's head lines (a pure deletion's base lines), else the whole file (`planChatMention`); in the dock, the item's current anchor (lines or file; change-wide and outdated notes are refused with a notice); in the tree, the focused file; with the palette open, the highlighted file or staged note. `@pierre/diffs`' gutter button (`enableGutterUtility` and `onGutterUtilityClick`; it refuses a custom button alongside the callback, so ours relabels the library's with a speech-bubble icon) adds the hovered line or the selection; dragging from it selects lines first. The chip goes in at the input's last caret, the sidebar switches to Chat and the input takes focus. A question holds at most 8 chips; the same lines twice are refused with a notice.
- **The input** is a `contenteditable="plaintext-only"` box whose DOM is a projection of a model, `DraftPart[]` (text runs and mentions, a chip counting as one caret position). Chips are `contenteditable="false"` spans built with `textContent`; the box is read back node by node, never through `innerHTML`. Pure functions edit the model: `insertDraftMention` (spaces the chip from adjacent words, caret after it), `removeDraftMention` (Backspace or Delete beside a chip removes it whole) and `serializeChatDraft`. ← / → beside a chip select it; Enter or a click on it jumps the diff stream to its lines, selected (base lines by their own numbers); Escape deselects. A question refused by main comes back into the input with its chips.
- **Grammar.** The question's text names the n-th mention as `[[@n]]` (1 to 99); a repeated mention is one mention named twice. Typed `[[@` becomes `[[ @`, so only chips make mentions. A token past the last mention stays text. `chat:ask` gains `mentions: [{ path, side: 'head' | 'base', startLine?, endLine?, sha }]` — both lines or neither (the whole file) — validated in main: at most 8, repository-relative paths (`normalizePathPrefix`), a full sha, `startLine <= endLine` and at most 5000 lines each.
- **Resolution at the commit** (`resolveChatMentions`, before anything is stored). A head mention must name the session head and a base mention the review's base (`ReviewView.baseSha`); otherwise it is refused ("selected at …, the review's head is now …; add it again"). A file of the diff is read by that side's blob from the diff itself, so an interdiff's base side is exactly what the card shows; any other path must be tracked at that commit (`git ls-tree`). Blobs are read with `git cat-file` (`readBlobs`, 2 MiB cap); binary, oversized and submodule files become an `unreadable` selection the prompt names. A start past the end of the file is refused, an end past it clamped (`excerptLines`), and all mentions together may span 20 000 lines. Refusals are `invalid-request` with a message the drawer shows.
- **Prompt.** A "Selected by the reviewer" section comes right after the change range, before the intent, ImpactGate findings and diff: each selection as `### Selection n: path:start-end (head|base <sha>)`, numbered as in its file, fenced as untrusted data. It is budgeted first: up to 60 000 characters in all and 30 000 per selection (`maxSelectionChars`, `maxSelectionFileChars`), within the overall budget less a fifth kept for the rest; a selection that doesn't fit keeps its leading lines and says which lines it left out and, for the head, to Read the file. The question is shown with each token as `«selection n: path:lines»`, followed by a note that it is about those selections, and the system prompt says such a question is about exactly those lines and that base lines are cited through the head. Answers' citations are validated as before (ADR 0031); one inside a selection's range resolves to the same jump target because both are `path:lines` at the head.
- **Persistence.** `chat-0002-mentions-and-summaries` rebuilds `chat_messages` (SQLite can't change a CHECK) keeping rowids, adding `mentions TEXT NOT NULL DEFAULT '[]'` (a JSON array that only questions may fill). A question is stored with its resolved mentions (ends clamped), and `chat:list` returns them, so the transcript renders the chips and they can be clicked. Earlier turns go back into later prompts with their tokens expanded and a `[beuve: selection n was …]` line, without the text: a follow-up names the lines and the model reads them again if it needs to.

## Consequences

The reviewer can say "this" and mean exact lines, both sides of a change included, and the model gets the bytes the reviewer saw at the commit they saw. Selections cost prompt budget ahead of the diff, so a whole-file mention can push diff hunks out; the prompt says what it dropped. A chip made before the head moved is refused rather than silently re-read at another commit, so the reviewer adds it again. Mentions are only re-sent as references, never re-read for later turns. The input is now an editable box rather than an `<input>`: single-line-ish (Enter sends), plain text only, with the chips owned by beuve.
