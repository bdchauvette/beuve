# 0035. A small GitHub REST client; diffs and history stay local in git

- Status: Accepted
- Date: 2026-10-28

## Context

beuve reviews GitHub pull requests the same way as local agent runs (spec 1): it needs a pull request's metadata (title and body for intent, base and head SHAs, forks), CI status, stack neighbours, and a way to post the URA review (ADR 0023). Octokit would add a large dependency tree for a dozen endpoints. GitHub's own diff is also the wrong source: beuve computes diffs, interdiffs and rebases locally with git (ADR 0010), and GitHub truncates large diffs.

## Decision

- **`src/internal/github/`**: a typed REST client on Node's `fetch`, injectable for tests, bound to one host (`https://api.github.com` or `https://<host>/api/v3`). It takes a structural `TokenSource` (`host → Result<{ reveal() }, E>`, satisfied by the auth domain's provider, ADR 0030) and passes `E` through as `{ kind: 'credentials' }`. Every request sends `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28` and a bearer token; paths are built with a percent-encoding tag, and a path or `Link` URL that resolves off the API root is refused, so a token can't be sent elsewhere.
- **Errors** (`GithubError<E>`): `unauthorized` (the caller invalidates the credential and may retry once), `forbidden` (with the SAML authorization URL from `X-GitHub-SSO`), `rate-limited` (403/429 with `x-ratelimit-remaining: 0`, `Retry-After` or a rate-limit message; `resetAt` from either header), `not-found` (also how GitHub hides private repositories), `validation-failed` (422 details, whether GitHub sends strings or objects), `unexpected-status`, `network`, `timeout`, `invalid-request`, `unexpected-shape`. Responses are validated with zod; nothing is cast.
- **Pagination** follows `Link: rel="next"` up to a page cap and reports truncation. **Conditional requests**: `getPullRequest` and `getCiStatus` take the previous ETag(s) and return `not-modified` on 304, which GitHub doesn't count against the rate limit; a check-runs ETag is kept only when the runs fit on one page.
- **Operations**: `parsePullRequestRef` (web URLs, `owner/repo#n`, `host/owner/repo#n`), `getPullRequest` (state folds `merged_at`; fork heads, deleted forks and pending mergeability are explicit), `listPullRequestCommits` (GitHub caps it at 250), `listPullRequestFiles` (paths, counts and whether a patch exists, patches dropped), `findPullRequestStack` (direct parents and children within the base repository only), `getCiStatus` (combined status plus check runs, bucketed into pending, success, failure, neutral and one overall state; `cancelled`, `timed_out`, `action_required` and `startup_failure` fail, `skipped` and `stale` are neutral) and `postPullRequestReview`.
- **Posting reviews**: one submitted review (`POST …/reviews` with `commit_id` = the head the URA was compiled against), so it is all or nothing. 422s become typed: `cannot-review-own-pull-request` (the UI offers COMMENT), `comments-rejected` (with the comment indexes GitHub's text names, which it usually doesn't), `stale-commit`. With `onRejectedComments: 'move-to-body'` it retries once with the named comments, or all of them, moved into the body (`moveCommentsToBody`, pure); a 422 creates nothing, so the retry can't duplicate. Network errors are never retried. The payload type is declared structurally and the ura domain's `GithubReviewPayload` is assignable to it.
- **What stays local**: diffs, interdiffs, file contents, blame and history come from git. `buildPullRequestFetch` returns, as data, `git fetch --no-tags --no-write-fetch-head --end-of-options <remote> +refs/pull/<n>/head:refs/beuve/pr/<n>/head` (and optionally the base branch into `…/base`); `refs/pull/<n>/head` lives in the base repository for forks too. Main runs it through the git domain's runner and checks the fetched ref resolves to the head SHA GitHub reported. `buildGithubRemoteUrl` gives the token-free HTTPS URL.
- **Git authentication** is not implemented here. Options, in order of preference: the user's existing remote and credential helper (osxkeychain, or `gh auth setup-git`, which installs `gh auth git-credential`); for a repository without a GitHub remote, the HTTPS URL with that helper; as a last resort, main passing `-c credential.helper=` plus `-c credential.helper=!<gh> auth git-credential` for that one fetch. Tokens never go into URLs, argv or the git config.

## Consequences

The client is a few hundred lines we own, with no Octokit, retries, throttling or GraphQL. Callers poll at their own pace and must respect `resetAt`. Redirects for renamed repositories are followed; fetch drops `Authorization` on a cross-origin redirect. Stack navigation sees only open pull requests in the same repository, one level at a time. GitHub's 422 texts for reviews aren't a documented interface, so classification is by pattern and falls back to `validation-failed`. The session domain's `github-pull-request` source has no host yet, so Enterprise pull requests need a host column before main can resume them.
