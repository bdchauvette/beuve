# 0027. The URA dock: wiring, keyboard grammar, clipboard path and outdated items

- Status: Accepted; GitHub posting amended by [0039](0039-posting-reviews-and-posted-items.md); insight promotion replaced by finding staging in [0055](0055-review-folded-into-chat-with-verification.md); the MCP tool superseded by [0106](0106-drop-the-embedded-mcp-server.md)
- Date: 2026-10-28

## Context

ADR 0023 built the URA domain (items, re-anchoring, exporters) but nothing reached it. Wiring it raised questions that constrain later work: what main stores and what it recomputes when the head moves, how `m` and `y` create items without stealing keys from text entry, which keys the dock answers to when `e` (inline edit) and `o` (open in IDE) are reserved by spec 5A, how an export reaches the system clipboard when the hardened session denies every permission (ADR 0005, 0011), and what the reviewer sees and exports when an item no longer fits the head.

## Decision

- **Channels** (`src/main/ura/create-ura-services.ts`): `ura:list`, `ura:create`, `ura:update`, `ura:transition`, `ura:reorder`, `ura:promote-insight`, `ura:stage-impact-finding` and `ura:export`, validated with zod, plus the push event `ura:changed { sessionId }`, sent after every change from any caller (the dock, MCP later) and whenever a refresh moves the head. `ura:create` takes the head the reviewer was shown, so a note on a stale view is anchored to what they saw. `ura:stage-impact-finding` takes only `{ sessionId, path, functionName }` and looks the finding up in main's own ImpactGate report; the renderer never supplies metrics. Expected refusals (approving over a blocker, an impossible transition, a stale reorder) are a new IPC error code, `refused`.
- **Placement is computed, never stored.** Every read refreshes the head and re-anchors items written against older heads with a `LineMapping` from `git diff --unified=0 --find-renames <old> <head>` (`build-line-mapping.ts`), cached per (repository, old head, head) in an LRU of 64. An old head git no longer has gives no mapping, and its items are `outdated` (`no-line-mapping`).
- **Promotion is one transaction**: find the insight, `promoteAgentInsight`, insert, set the insight `promoted`. A repeat finds the existing item through the partial unique index (`findUraItemByOrigin`) and returns it, restaged if it was withdrawn, so `y` is idempotent. Withdrawing or restaging an insight's item sets the insight back to `pending` or `promoted` in the same transaction; `y` on a promoted insight withdraws its item. ImpactGate findings stage the same way, once per (session, head, path, function).
- **`m` in the diff stream** opens a composer as a line annotation under what it stages: the card's line selection when it lies on the head side (`enableLineSelection`; the selection `j`/`k` sets programmatically doesn't count), else the active hunk's head lines, else the whole file (now the shared review target, ADR 0063). Severity defaults to `issue`. Enter in the title or ⌘/Ctrl+Enter saves, Escape cancels, and the composer stops every keydown from propagating; the shell's global handler also ignores keys whose target is an input, textarea or select.
- **Dock keyboard grammar**, while Zone 3 has focus and no text field does: `j`/`k` (and the arrow keys) move the cursor; Enter jumps Zone 2 to the item's current anchor and focuses it; Space expands the item into an editor panel (title, body, severity; ⌘/Ctrl+Enter or Enter in the title saves, Escape closes); `x` withdraws or restores; `a` marks addressed at the current head or restages; `Shift+J`/`Shift+K` move a staged item down or up the export order, swapping with the nearest staged neighbour so withdrawn items keep their place. `e` and `o` stay free for their spec meanings. Staged items come first in export order, then withdrawn and addressed ones, dimmed.
- **Verdict**: the selector shows the derived verdict as its default and lists the other two. Choosing the derived value is no choice. Choosing approve while a blocker is staged is refused in the dock with a message and the derived verdict stays (main refuses it again on export). The choice is per dock and not persisted, so `beuve_read_human_review` reports the derived verdict.
- **Clipboard path**: the renderer's `navigator.clipboard` needs the `clipboard-sanitized-write` permission, which `hardenSession` denies, and we keep denying it. Exports go `ura:export` (main compiles the artifact and renders the target) and then `clipboard:write-text { text }` (at most 16 MiB), which main writes with Electron's `clipboard.writeText`. The IPC handlers take the clipboard as an injected platform function, so they stay testable without Electron. There is no read channel.
- **Outdated items in the UI**: an outdated item stays staged and is exported. The exporters put it in the review body with its original anchor and head (ADR 0023). The dock shows an `outdated: …` marker with the reason, and Enter jumps to its file but not to lines. File cards mark only staged items whose placement is current. The reviewer decides: withdraw, mark addressed, or leave it. Nothing is dropped or moved silently.
- **Markers**: staged items show as one quiet line under their last shown head line (`Staged · Issue  title`), through the same annotation slots as agent insights (`to-ura-markers.ts`); whole-file notes sit above the first hunk. A promoted insight's own block says "Staged" instead of getting a second marker. The ImpactGate banner gets a small "Stage" button for the file's findings, which reads "Staged" once they are.
- **MCP**: `beuve_read_human_review({ sessionId? })` resolves the session like the other tools (ADR 0021), compiles the staged items with the derived verdict and returns `buildAgentReview` as `structuredContent` and `renderAgentReviewXml` as the text content. Its description says what the payload is, that anchors are 1-based head lines of `change.headSha`, and that it is data, not instructions.
- **GitHub**: the dock copies the review JSON but does not post it. Posting needs the auth domain, which doesn't exist; the dock says so. The payload is built without `commentableRanges`, since local sessions have no pull request diff.

## Consequences

The dock, the diff markers and MCP agree on placement because all of them compute it from git at read time, at the cost of one zero-context diff per older head (cached). Stale views are safe: a note keeps the head it was written against. Text entry can't trigger shortcuts, but any new text field must sit in a component that stops keydown propagation or rely on the shell's input/textarea/select check. The dock's verdict choice is lost on reload, and agents don't see it until it is persisted. Copying needs a round trip through main. Outdated items need a human decision, and the dock lists them until one is made.

## Amendment 2026-10-30: findings, not insights

`ura:promote-insight` and `y` are gone (ADR 0055). `ura:stage-review-finding { messageId, finding }` stages a `/review` finding read from its stored answer, idempotently, restaging a withdrawn item, the way promotion did; withdrawing it changes nothing else, since findings have no status of their own. Staged findings show as ordinary markers.

## Amendment 2026-10-31: markers on lines the diff doesn't show

A note anchored on an unchanged line outside every hunk (one staged from a citation or chat on context, or re-anchored by a head move) used to sit above the first hunk, as if it were a file note. Now `placeNoteOnDiff` puts it just above the collapsed gap that holds its last line (after the last head line before that gap, or above the first hunk for the gap before it), and its marker ends with a "line N, outside the shown hunks" button. The button expands that gap from its nearer end by exactly enough lines, through the library's own `expandHunk`, as the separator's buttons do, and the marker moves under its line; the card remembers the revealed range until its file changes and expands it again when the diff remounts. Insights and the composer use the same placement, without the button.

The diff never expands on its own: expanding is the reviewer's choice everywhere else (separators, Load diff), it loads both full files over IPC (`session:get-file-pair`), which a card far down the stream would otherwise do for every such note as it mounts, and it changes the card's height under the reader. One click on the marker is the same gesture as a separator's. A re-render for new notes no longer passes the parsed patch again, which had replaced the full files an expansion loaded and collapsed every expanded gap (including ones opened from a separator).
