# 0042. Diff display modes, the whitespace-ignoring variant, and the ImpactGate chip

- Status: Accepted
- Date: 2026-10-29

## Context

Diff cards rendered every file inline (ADR 0025). Reviewers asked for side-by-side diffs by default, an inline toggle and a way to hide whitespace-only changes. Each touches something later work depends on: URA items, insights, ImpactGate findings, peek/flow/trace targets and `o` all speak in head line numbers (ADR 0023, 0027, 0029, 0033), `j`/`k` and `m` select rows in the library's DOM, and ImpactGate's banner took a full row in every card header.

## Decision

- **Layout.** `@pierre/diffs` renders `diffStyle: 'split'` or `'unified'`. `planDiffLayout(status, preference, streamWidth)` decides per card: added and deleted files are always one full-width column (`single-sided`, no empty half); otherwise the preference, except that below 900 px of diff stream (`minimumSplitWidth`, measured with a `ResizeObserver`) a split falls back to inline (`narrow`). The review header shows a quiet `Split`, `Inline`, `Inline (narrow)` or `… · whitespace hidden` with a tooltip naming the keys. Changing the style recreates the card's `FileDiff` in a fresh container.
- **Keys and commands.** `s` toggles split/inline and `w` toggles whitespace in the diff stream (both were unbound); `/diff split|inline` and `/whitespace ignore|show` do the same from the chat, and without an argument say what is current. The keybinding overlay lists the keys and the current display.
- **Persistence.** `display:get` / `display:set` keep `diffLayout` and `ignoreWhitespace` in `<userData>/settings.json` next to the editor preference (ADR 0033). Defaults: split, whitespace shown.
- **Whitespace is computed by git, in main.** `session:get-review { ignoreWhitespace: true }` diffs with `--ignore-all-space` (`-w`), for full reviews and interdiffs alike (the option is threaded through `diffRange` and `computeInterdiff`), and `ReviewView.whitespace` says which variant it is. We chose `-w` over `--ignore-space-change` (`-b`): it is what GitHub's "Hide whitespace" uses, so the view agrees with the pull request page, and it also hides reformatting that adds or removes spaces where there were none (`a+b` → `a + b`), which `-b` keeps. Files whose only changes are whitespace drop out of the variant (older gits print a bare header; we filter those). Each variant is a separately cached display diff: session services keep an LRU of 16 diffs keyed by repository, base tip, range commits and variant, so toggling back and forth runs git once per variant. Only `session:get-review` serves the variant; ImpactGate, the agent review, chat, trace, flow, LSP and the file pair keep the plain diff.
- **Anchoring is unaffected.** `-w` changes which lines count as changed, never line numbers: every hunk still numbers both sides by the real files, and context lines carry their head text. URA items, insights, ImpactGate findings and trace lines stay head-side line numbers of the same head and are placed exactly as before; a marker or insight whose lines no `-w` hunk shows any more sits above the card's first hunk, like any range the patch doesn't show (ADR 0025), and one on a file `-w` hid has no card until whitespace is shown again (the dock still lists it). "Mark reviewed" records the head as before, whitespace changes included. The parsed-diff cache key includes the hunk headers, since both variants share blob ids.
- **Head lines in both layouts.** Rows are found with `headRowSelector(style, kind, line)`: inline in `code[data-unified]`, where context rows carry head numbers; split in `code[data-additions]` for added and context rows and `code[data-deletions]` only for deleted ones, because left-hand context rows carry base numbers. Annotations stay `side: 'additions'`, so insights, URA markers and the `m` composer sit on the right in split mode. `planHunkSteps(hunks, style)` makes `j`/`k` select a replacement on its head side when split and keep a pure deletion on the left; `m`'s and `o`'s head-side rules are unchanged. Revealing a row scrolls vertically and keeps the code's horizontal scroll.
- **ImpactGate in the title bar.** The banner row is gone. `planImpactChip` drives a compact indicator next to `+/−`: nothing when no function changed (or the language isn't read), a faint gauge mark for an analyzed change without findings, a warning chip with an icon and the worst value (`cognitive 23`, `+1` for more) when a function is over the limit, and a neutral `skipped` note. The chip is a button; hovering it, focusing it, or `i` on the focused card opens a popover (the Popover API's top layer, so cards' `overflow: clip` can't cut it) with the summary, each changed function's lines, cognitive before → after, percentile and trend, and the Stage action. Escape closes it and returns focus to the stream; it never traps focus (Tab moves through it and on). The radar tree's decorations never read the banner and are unchanged.

## Consequences

Split is the default and new files read full width; narrow windows degrade to inline on their own. Hiding whitespace costs one more `git diff` per head, cached. In Python, YAML or Makefiles `-w` can hide a meaningful indentation change; the header says whitespace is hidden while it is. Comments and suggestions are still anchored on the real head lines, so nothing exported depends on the display. Split annotations are half as wide as before. The popover is positioned from the chip's rectangle when it opens and doesn't follow a scroll; it closes when the pointer or focus leaves.
