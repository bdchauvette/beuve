# 0141. Notes the agent raised say so on GitHub, with a finding's confidence

- Status: Accepted
- Date: 2026-11-18

## Context

A reviewer can stage a `/review` finding (ADR 0055) or a note a chat answer proposed (ADR 0132) and post it to GitHub (ADR 0039). On the pull request it then reads exactly like a note the reviewer wrote, so the author can't tell an agent's guess from the reviewer's judgment. A finding comes with the model's own confidence (0–1, `finding-output-schema.ts`), which the chat drawer shows, but staging dropped it, so nothing downstream could say how sure the agent was. Review summaries carry no attribution of their own: the reviewer writes them.

## Decision

- **The confidence is kept.** `ura-0003-finding-confidence` adds `ura_items.chat_confidence` (REAL, NULL or 0–1, only on a finding). `UraOrigin`'s `chat-answer` gains an optional `confidence`, set only with `finding`, validated like the rest of the origin and carried to `UraOriginView`. Findings staged before it, proposed notes and human notes have none. The finding's category is not kept: nothing shows it after staging, and the category list belongs to the chat domain, which the URA domain can't import.
- **GitHub output signs the agent's notes.** `buildGithubReview` (the posted review and File › Export Review's GitHub JSON) ends the body of every `chat-answer` note, inline or in the review body, with a rule and an italic line, after any suggestion block:

  ```
  ---

  _Generated by agent review. Confidence: 50%_
  ```

  The percentage is rounded to a whole number, as the chat drawer shows it. A note with no confidence ends `_Generated by agent review._`. The line is plain Markdown, so it reads the same in email notifications. Human notes and the reviewer's summary get nothing.

- **The footer stays after the reviewer edits the note.** An item's origin never changes (ADR 0023), and the footer states where the note came from, not who wrote each word. Telling a light edit from a rewrite would be a guess, and dropping the footer on any edit would let one keystroke hide an agent's note. The confidence is the agent's estimate for its finding and is not changed by an edit either. A reviewer who wants a note of their own writes one, and can withdraw the agent's.
- **The agent format carries it as data.** `beuve.ura/1` (`docs/review-format.md`) gains an optional `confidence` attribute on a finding's `item` (`origin.confidence` in the JSON form), as the number stored, not footer prose: an agent reading the export already has `origin`. Adding an optional attribute keeps `beuve.ura/1`. The document now states the rule: removing, renaming or redefining something, or adding a value to a closed list, makes `beuve.ura/2`; adding an optional attribute or child does not, and readers ignore what they don't know.
- **The dock shows it.** The origin text of such a note reads `review finding · 50%` (`describeUraItem`), which the dock row and the diff marker's tooltip already show.
- **Later migrations run after every earlier one** (ADR 0006 amendment 2026-11-18): a migration added after the initial ones lives in its own file and is appended to `appMigrations` in the order written, so an upgraded database and a fresh one apply the same sequence.

## Consequences

The author of a pull request sees which notes an agent raised and how sure it was, and a reviewer can't post an agent's note as their own without rewriting it as a new note. Posted bodies of agent notes are two paragraphs longer. Notes staged before this change post with the footer but no confidence. The schema-fixture script's seed rows don't set `chat_confidence` yet; they gain it when the next release's fixture is written.
