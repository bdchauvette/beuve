# 0055. `/review` is a chat answer, with findings checked by a second pass

- Status: Accepted; supersedes [0022](0022-opt-in-preliminary-review-via-chat-command.md) and [0024](0024-review-runs-keyed-by-path-scope.md), amends [0019](0019-review-model-port-and-claude-code-cli-adapter.md), [0023](0023-universal-review-artifact-model-and-exporters.md), [0027](0027-ura-dock-keyboard-clipboard-and-outdated-items.md) and [0030](0030-llm-domain-and-structural-model-ports.md)
- Date: 2026-10-30

## Context

The preliminary review (ADR 0019, 0022, 0024) had its own domain, two tables (`review_runs`, `agent_insights`), three `review:*` channels, a progress event, path-scope keying, status carry-over across reruns, purple insight blocks inside the diff cards, `]`/`[`/`y`/`d` keys and `ura:promote-insight`. The chat (ADR 0031) already had everything a review needs to reach the reviewer: a transcript, citation pills that jump the diff, staging into the URA and the same model adapter. The complexity audit recommended merging the two, and the review-tools research found that what makes AI review usable is precision, not recall: Claude Code Review runs find, verify, dedupe and rank, and benchmarks that ignore false positives mislead. Research also warns that reviewers shown an AI review first check less elsewhere ("blind first"), so nothing should appear on its own.

## Decision

- **`/review [paths…] [--fresh] [--no-verify] [--effort=low|medium|high]` is a chat request**: `chat:ask { question, command: { kind: 'review', pathPrefixes?, fresh?, effort?, verify? } }`. It is stored as a question (what was typed) and an assistant message of `kind = 'review'`, and it queues like any question (ADR 0057). It runs only when the reviewer types it; nothing runs on session load or in the background.
- **What moved into the chat domain**: the schema-constrained JSON output (`findingOutputSchema`, at most 50 findings, sent with `--json-schema`; `ReviewModel` is the chat domain's structural port for `run`, beside `ChatModel` for `runText`), path-scope normalization (`normalizePathScope`) and filtering (main's `toChatQuestion`, a prefix matching that path and below on either side of a rename), and out-of-diff validation (`validateFindings`: head-side text file of the diff, touching a hunk, narrowed to it, confidence at least 0.3, deduplicated, the 12 most severe and confident kept, in diff order). The prompt is the chat's (`buildChatPrompt`) with a task in place of the question and its own system prompt (`ChatTask`), so the diff budget and fencing are shared, not duplicated.
- **Verification** (`verifyFindings`, then `reviewChange`): after validation, a second run of the same adapter with `--effort=low`, read-only tools and a schema of `{ finding, verdict: confirmed | refuted | unsure, reason }` per numbered finding. Its prompt holds the findings (fenced as untrusted) and the change range, not the diff, so it judges the code at the cited lines rather than the first pass's reading of it. Refuted findings are dropped and counted (`dropped.unconfirmed`, shown as "n dropped as unconfirmed"); `unsure` or unanswered ones are kept and marked `unconfirmed`; confirmed ones are marked so. Both passes share one deadline (`claude.timeoutMs`, else 10 minutes); the second gets what is left and is skipped below 5 seconds. A failed second pass keeps the findings `unchecked` and says so (`verification: 'failed'`); a cancellation fails the request. `--no-verify` skips the pass (`verification: 'skipped'`).
- **Storage** (squashed into `chat-0001-initial`, ADR 0006): `chat_messages` gains `kind` (`answer | review | abstract`, assistants only) and `review` (JSON, only on a completed review answer): the findings with severity, category, confidence and check, the drops by reason, the path scope, the file count, the verification state and `reusedFrom`. The answer's `content` is a Markdown rendering with a `[[path:start-end]]` per finding, so later questions see the review as an earlier turn, and `citations` lists the findings' ranges.
- **Reuse instead of a run store**: without `--fresh`, a review whose head and normalized scope match the latest completed review answer before it repeats that answer (`reusedFrom`), with no model call. Effort is not part of the match (ADR 0024's rule).
- **Transcript**: a calm list, one item per finding: severity (risk red, warning amber, info muted), category, confidence, "✓ confirmed" or "unconfirmed", the title and a Markdown subset of the body (text nodes only), one citation pill and a Stage button. A summary line above says files, findings and what was dropped and why. Progress is a `chat:delta` of kind `progress` (coarse text, never content).
- **Staging a finding**: `ura:stage-review-finding { messageId, finding, severity? }`. Main reads the finding from the stored answer (the renderer never supplies its text), and stages it on its lines at the answer's head with origin `{ kind: 'chat-answer', messageId, finding }` (`ura_items.chat_finding`, a partial unique index on (message, finding) so staging is idempotent and a withdrawn item is restaged). Severity maps as before: risk and warning become `issue`, info `nit`. The URA origin `agent-insight` and `insight_id` are gone; a finding is a chat answer with an index, which keeps the URA model small.
- **Removed**: `src/internal/review` (and `review_runs`, `agent_insights`), `src/main/review` (Claude Code resolution moved to `src/main/chat`), `review:run`, `review:list-insights`, `review:set-insight-status`, `review:progress`, `ura:promote-insight`, the insight blocks and `place-insights`, the insight palette group, and the `]`/`[`/`y`/`d` keys. `--beuve-insight` is now `--beuve-violet`. MCP had no insight tool; `beuve_read_human_review` now names staged chat answers and findings as origins.

## Consequences

- One LLM surface: every model call is a chat request, queued, cancellable and stored in one table. The change removes about 1,900 lines net (code −4,100 +2,700, tests −1,900 +1,400), with `/summarize` and the queue included.
- Findings no longer appear on the diff lines by themselves; the reviewer reads them in the transcript and jumps with the pill, or stages one, which then shows as an ordinary staged marker. There is no dismiss state that survives reruns: a rerun is a new answer, and what matters is what was staged.
- Each verified review costs a second, cheaper model call. The verifier is the same model family and can share the first pass's blind spots; it lowers false positives, it does not prove a finding, and a clean review still says it built and ran nothing.
- `/clear` deletes review answers with the rest of the chat; staged findings stay, because `chat_message_id` has no foreign key.
