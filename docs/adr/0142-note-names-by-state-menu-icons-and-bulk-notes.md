# 0142. Note commands named by their state, menu icons, dragging notes, and changing several at once

- Status: Accepted; amends [0068](0068-native-menus-chorded-keymap-and-a-settings-window.md) (catalog fields), [0023](0023-universal-review-artifact-model-and-exporters.md) (deletion) and [0027](0027-ura-dock-keyboard-clipboard-and-outdated-items.md) (dock keys and channels)
- Date: 2026-11-18

## Context

Review › Note named two commands by their mechanics rather than what they do: "Withdraw or Restore Note" whatever the note's state, and "Note Addressed", a checkbox that is not a verb. Move Up and Move Down read alike in a menu of short labels. Reordering the review notes took one ⌥↑/⌥↓ step at a time, and every Note command acted on the single note under the cursor, so relabeling, withdrawing or deleting ten agent findings took ten rounds, and Undo only brought back the last one deleted.

The catalog (ADR 0068) had no way to name a command by the state of what it acts on: `toggle` shows a check mark under a fixed label, and the only dynamic menu was Open With's list of editors (ADR 0139), which main owns. It had no way to put an image beside an item either.

## Decision

- **Names that follow the state.** A catalog command may declare `checkedNames: { title, label? }`: the names it takes while the window lists it in `menu:set-state`'s `checked`, which already carries the toggles' checks, so no channel changes. Such a command has no `toggle` (a test holds that) and shows no check mark. `menuTemplateFrom` gives its item both labels, each with its own Linux access key, and `contextMenuTemplateFrom` both titles; `createAppMenus` keeps the checked label out of Electron's options and swaps `label` in place on every state, which Electron 45 documents as dynamic, so menus are not rebuilt. The palette shows the checked title for the commands the window passes as `checked` (the dock's state, whether or not the dock has the focus, since a Note command from the palette acts on it). The Keyboard Shortcuts window shows both names ("Withdraw Note or Restore Note"), because the in-place key does both.
- **The note commands use it.** Withdraw Note / Restore Note (label Withdraw / Restore); Mark Note as Addressed / Mark Note as Not Addressed (no longer a checkbox); and the new Mark Note as Blocking / Mark Note as Not Blocking. With several notes selected, a command shows its checked name only when every selected note is in that state: Restore when all are withdrawn, otherwise Withdraw, which withdraws the staged ones and leaves addressed ones alone (a note is restored before it changes between withdrawn and addressed, ADR 0023). `dockItemOf` reports `{ count, isAddressed, isWithdrawn, isBlocking }` for the selection, and `dockCheckedCommands` turns it into the checked ids for both the menus and the palette.
- **Menu icons.** A catalog command may declare `icon`, one of a closed `MenuIcon` list (`arrow-up`, `arrow-down`); Move Note Up and Move Note Down use them in Review › Note and the note's context menu. The template carries the name, and `createAppMenus` turns it into a `NativeImage` once per theme. On macOS it is the SF Symbol (`arrow.up`, `arrow.down`, `nativeImage.createFromNamedImage` at 13 points) marked as a template image, so it takes the menu's color and selection; should the symbol be missing on an older macOS, beuve's own drawing serves as the template instead. Linux has no template images, so main draws the arrows itself (`drawMenuIcon`: two-pixel-per-point premultiplied BGRA, round-capped strokes, 4×4 supersampled) in a light or dark ink for the current theme, and redraws the menus when the theme changes. No image file is shipped, so `electron-builder.yml` is unchanged and there is no third-party artwork to license. **Not verified from this container:** how the SF Symbol renders in a real macOS menu (its size and baseline); the drawing is the fallback if it looks wrong.
- **Dragging notes.** A staged note is `draggable` (not while its editor is open) and drags among the staged ones only: withdrawn and addressed notes neither move nor take a drop, as with ⌥↑/⌥↓. Over a staged note, an accent bar (`--beuve-accent`, `--beuve-border-width-thick`) in the gap above or below it, by the pointer's half, shows where the note lands. `dropUraItems` (pure) computes the new order, the dragged notes landing together in their old order and the others keeping their slots, and the drop goes through the same `ura:reorder` Move Up and Move Down use; the cursor follows the dropped note. The drag carries the ids under a private type (`application/x-beuve-ura-items`) that no text field takes. Every drag event is delegated (`dragstart`, `dragover`, `drop`, `dragend` on the item, `dragleave` on the list; ADR 0074). Keyboard reordering is unchanged.
- **Selecting several notes.** The dock keeps a selection beside its cursor (`dockSelectionAfter`, pure, with an anchor as list views have): ⇧↑/⇧↓ and Shift+click select the range from the anchor, ⌘-click (Ctrl+click on Linux; on macOS Ctrl+click is the context menu) adds or removes one note starting from the cursor's, a plain arrow or click clears it, and Escape clears it. ⌘A / Ctrl+A selects every note while the list has the focus: it is an in-place key the dock handles and prevents, so Edit › Select All's role never sees it there and keeps working in every text field (the catalog's in-place keys gain `linuxKeys` for keys that differ by platform); Review › Note › Select All is its menu item. The Note commands except Show in Diff, Edit Note… and Open in Editor act on every selected note, in dock order; Move Up/Down move them as a block (`moveUraItems`), and dragging a selected note drags the selected staged ones. A bar above the list says "3 notes selected" and holds the shared `beuve-ura-label-menu`: a label choice relabels them all, Blocking blocks them all or, when all block already, none. Change Note Label… puts the keyboard on that menu, or opens the single note's editor on its label. A right-click on a note outside the selection clears it, so the context menu acts on the note it was opened on.
- **Batches in one call.** `ura:edit-many { itemIds, change }` changes the status, label or Blocking of up to 1000 items of one session, all or none, in one transaction, and leaves alone those already in the asked-for state; the dock sends every status change through it. `ura:delete` takes `itemIds` and keeps them as one deletion with an id; `ura:restore { deletionId }` puts all of them back in their old places in one transaction. Main still remembers the 20 latest deletions, now of any size, so Undo Delete Note restores the whole selection ("Deleted 3 notes." / "Notes restored."). `withResultTransaction` (`src/sqlite`) rolls back a transaction whose work returns a failure. `ura:transition` stays for one item.

## Consequences

A command whose action flips with its subject now says what it will do, in the menus and the palette, from one catalog field, and any command can get an icon by naming one in the list (adding one means drawing it in `drawMenuIcon` and naming its SF Symbol). The menus still do not show counts ("Withdraw 3 Notes"): names are static per state, and the selection bar shows the count. Labels change in place on every state report, which relies on Electron keeping `label` dynamic. The Linux arrows are beuve's drawing, not the desktop's icon theme. Dragging and selection add state to the dock that it must prune when items change (it does, on every `items` update). A batch is all or none: one note that cannot be marked addressed on the head it was written against refuses the batch, with the reason, rather than marking the rest.
