# 0065. Review file order: path, imports or calls, config and mechanical last

- Status: Accepted
- Date: 2026-10-30

## Context

The diff lists files in path order. A reviewer who meets `app.ts` before the helpers it calls has to guess what they do. Fregnan et al. (FSE 2022) also found that a defect in the last file was spotted far less often (64% less), so what comes last matters. The evidence on the best order is unsettled and no experiment tested test-first ordering, so the order is the reviewer's choice, saved as a preference, and beuve does not reorder tests: normal sorting places them.

## Decision

- **Channel.** `session:get-order { sessionId, mode? }` answers `{ headSha, requestedMode, mode, fallback?, paths, groups }`: `groups` are the ordered runs (`changes`, then `config-and-mechanical` with a `reasons` list aligned to its paths), `paths` their concatenation, all head paths of `ReviewView.files`. Without `mode` the saved preference applies. The preference is `reviewOrder` (`path` | `imports` | `calls`) in `settings.json`, read and written through `display:get` / `display:set` beside the other display preferences. Computation lives in main (`src/main/order/`), over the plain diff of the review; pure parts are in the session and syntax domains.
- **Path.** Code-point order of the head path, which is git's own order.
- **Imports: dependencies before dependents.** Reading a file after the code it uses lets the reviewer know what each call does when they reach it; the reverse reads top-down but leaves every reference unresolved. The walk is a depth-first post-order in path order: each file is placed right after the changed files it imports, so a file's helpers sit beside it rather than in a far-off layer. An edge that would close a cycle is ignored, so a cycle is cut at its first path in sorted order, the same every time. Edges only join ordinary changed files; imports of unchanged files and packages add none.
- **Import extraction and resolution.** The syntax domain reads `import … from`, `import 'x'`, `import x = require()`, `export … from`, `import()` and `require()` with a string literal from TypeScript, TSX and JavaScript trees (`extractModuleReferences`, ADR 0014). `createModuleResolver` resolves, over the head's tree listing and the `package.json` / `tsconfig.json` blobs read from git (never the working tree): relative specifiers with extension, emitted-extension (`.js` for `.ts`) and `index` probing; `#alias` through the nearest enclosing `package.json` `imports` (patterns, and `types`/`import`/`node`/`default` conditions); and `tsconfig.json` `paths` with `baseUrl` from the nearest tsconfig that has them. `extends` chains and bare packages are not followed.
- **Calls.** For each changed TypeScript or JavaScript file (at most 40) main asks the language server for the outgoing calls of the function around the first added line of each of its first three hunks, four requests at a time, and keeps calls into other changed files. This is a dependency order like imports, over what the code calls instead of what it imports. When no server answers (`unsupported`), or no call reaches another changed file, the order falls back to `imports` and `fallback` says `no-language-server` or `no-call-edges`; with no TypeScript or JavaScript file to read, either mode falls back to `path` with `no-source-files`.
- **Config and mechanical files go last, in their own group, in every mode.** `classifyReviewFile` is pure and its rules are data (`mechanicalRules`), first match wins: lockfiles (`package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `Cargo.lock`, `go.sum`, …); generated (`linguist-generated` per `.gitattributes`, `*.min.js`, `*.map`, `*.pb.go`); pure renames (100% similar); formatting-only (the file's diff is empty under `git diff --ignore-all-space`); config (`package.json`, `tsconfig*.json`, `*.config.{js,ts,mjs,cjs,mts,cts,json,yaml}`, `.github/`, eslint, prettier, stylelint, dependency-cruiser, `.editorconfig`, `.gitignore`, `.gitattributes`, `.nvmrc`, `.node-version`, `.npmrc`, and `*.yml`/`*.yaml`/`*.toml` at the repository root). The group is sorted config, pure rename, formatting-only, generated, lockfile, then path, so the noisiest sit last.

## Consequences

The reviewer can pick the order that suits the change, and the config noise no longer sits among the code. `calls` costs language-server round trips (and a session checkout) the first time; `imports` costs one tree listing, the config blobs and a parse of each changed source file, cached per head for the resolver. Resolution is textual: it misses aliases that need `extends`, workspaces' package exports and generated paths. Position bias is not removed, only made adjustable; the UI should show where the reviewer is in the list.
