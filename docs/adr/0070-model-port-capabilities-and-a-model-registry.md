# 0070. Model capabilities, messages and a model registry with roles

- Status: Accepted; amends [0019](0019-review-model-port-and-claude-code-cli-adapter.md), [0030](0030-llm-domain-and-structural-model-ports.md), [0046](0046-chat-context-mentions.md), [0055](0055-review-folded-into-chat-with-verification.md), [0068](0068-native-menus-chorded-keymap-and-a-settings-window.md) and [0069](0069-agent-sdk-adapter-with-an-api-key.md)
- Date: 2026-10-30

## Context

beuve had one hard-wired model: main's `resolveLanguageModel` built the Claude Code CLI adapter for every request, the Agent SDK adapter of ADR 0069 had no caller, and the port assumed what Claude Code can do: read the worktree with tools, constrain output to a JSON Schema, and fit a fixed prompt budget (200k characters). The goal is to add a model from the Settings window, including local models behind an OpenAI-compatible server ([0071](0071-openai-compatible-adapter.md)) that may have no tools, prompted structured output and an 8k–32k context window. Each request also flattened the diff and the question into one prompt, so an API that caches prompt prefixes could not reuse the diff between questions at one head.

## Decision

- **Port** (`src/internal/llm/language-model.ts`), additive apart from the prompt:
  - `LanguageModel.capabilities`: `{ tools, structuredOutput: 'native' | 'prompted', contextWindowTokens: number | undefined, maxOutputTokens?, streaming }`, per configured model. Both Claude Code adapters report tools, native output and streaming; the window is the entry's, else unknown.
  - Requests carry `messages` (ordered `user`/`assistant` turns, the last the user's) instead of `prompt`, each with an optional `cache` flag marking the end of the stable prefix. The chat sends two: the change (diff, ImpactGate findings, stated intent, omissions), marked `cache`, and the request (selections, compaction summary, earlier turns, focus, question or task). **The selections now follow the diff** (ADR 0046 put them first); they are still budgeted before it. Adapters that take one prompt join the messages (`flattenModelMessages`); the OpenAI-compatible adapter sends them as messages.
  - `effort` and `model` per request override the adapter's configured defaults. `/review --effort` sets the first pass's effort and the verification pass asks for `low` (ADR 0055) through the request, not by building a second adapter.
  - Progress is `started(model)`, `thinking(summary?)`, `tool-start { id, tool, description }`, `tool-end { id, tool, ok }`, `text-start`, `text-end`. A description names what a tool looks at (`read src/auth.ts:1-40`, `grep validate(`, `glob **/*.ts`, at most 80 characters on one line), never what it found. The Claude Code adapters share one stream reader (`ClaudeCodeStreamReader`), which also reads `content_block_start`/`stop` and the top-level `user` tool results. The `/review` status line shows the latest description.
  - `ModelError` gains `unsupported-version { command, version, required }`.
- **Budgets and wording from capabilities** (chat domain): its structural ports take optional `capabilities: { tools, contextWindowTokens }`. `chatPromptBudgetFrom` keeps the old budget when the window is unknown, and otherwise gives a quarter of the window to a model with tools and half to one without, at 3.5 characters per token, between 12k and 600k characters, every limit scaled from the defaults with floors; `/compact`'s budget scales the same way. Without tools, no prompt or system prompt mentions Read, Grep, Glob or the working directory: truncation notes say "not shown", omitted files "you cannot see them", and the verification pass is shown the diff hunks each finding touches instead of being asked to read the lines.
- **Registry** (main-owned, `src/main/models/`), under `models` in `settings.json`: `{ entries, roles }`. An entry is `{ id, label, kind, model?, effort?, contextWindowTokens?, apiKeyRef? }` plus, per kind, `executable: { source: 'installed', path? } | { source: 'bundled' }` (`claude-agent-sdk`) or `baseUrl` and `tools` (`openai-compatible`). The default registry has one entry, `claude-code`, "Claude Code (your login)", kind `claude-code-cli`: today's behaviour. It can be edited but not removed or changed to another kind. Roles `chat`, `review`, `verify`, `summarize` and `compact` each name an entry (all `claude-code` by default); a role naming a removed or invalid entry falls back to it. The stored registry is read leniently (bad or duplicate entries are skipped), and entries are validated in main with zod (bounded text without control characters, absolute paths, http(s) URLs without credentials, nothing unknown).
- **Resolution**: `resolveLanguageModel({ role } | { entryId }, deps)` reads the registry per request and builds the entry's adapter: the CLI adapter with `claude` found as before (ADR 0022); the Agent SDK adapter with the stored key, on the bundled binary or the installed `claude`; the OpenAI-compatible adapter with its key, tools setting and a context window defaulting to 32,768 tokens. Failures are `ModelError`s, so the chat stores them like a failed run; the chat's error texts now name "the model" and point at Settings ▸ Models. Questions use `chat`, `/review` `review` and `verify`, `/summarize` `summarize`, `/compact` `compact`. MCP is unaffected.
- **Agent SDK executable**: Installed (the default) uses the entry's path, or finds `claude` like the CLI adapter, then runs `<path> --version` (five seconds, no shell) and refuses one older than the SDK's pinned Claude Code (`pinnedClaudeCodeVersion` = 2.1.312, kept equal to the SDK's `package.json` `claudeCodeVersion` by a test) with `unsupported-version`: "… older than 2.1.312, the version the Agent SDK speaks. Update it, or switch the executable to Bundled." A path is also checked when the entry is saved. Bundled uses the SDK's platform binary, which `electron-builder.yml` now copies into the app (it excluded all of `node_modules`) and unpacks from the archive so it can run; main passes its `app.asar.unpacked` path, and unpackaged builds let the SDK find it in `node_modules`. The binary adds about 280 MB to the unpacked app (measured below).
- **Secrets**: API keys live in `<userData>/model-secrets.json`, never `settings.json`, as base64 of Electron's `safeStorage` ciphertext (`encryptStringAsync`/`decryptStringAsync`; the synchronous calls are deprecated in Electron 45), written atomically with mode 0600. The store depends on a `SecretCipher` interface, so main's services and tests need no Electron; tests use a reversible fake. Without encryption no key is stored. On Linux without a keyring Electron falls back to a fixed key (`basic_text`); Settings says so. Entries hold only `apiKeyRef`. Keys go one way: `models:set-key` sends one, every view says only `hasApiKey`, an invalid `set-key` request is refused without quoting it, keys are never logged, and a model list request (`models:list-remote`) uses an entry's key only for that entry's own base URL.
- **Channels** (Settings window only): `models:list`, `models:save`, `models:remove`, `models:set-role`, `models:set-key`, `models:remove-key`, `models:list-remote`, `models:test`, listed in `settingsOnlyInvokeChannels`. Main registers the main window with `mainWindowInvokeChannels` (every channel but these) instead of `all`, the main preload refuses them, and the Settings preload allows them. Every request is validated in main.
- **Test**: `models:test { id }` runs `runText` ("Reply with the single word: ok") through the chat services' queue (a queue key no session id can take, ADR 0057) in an empty scratch directory, and answers `{ outcome: 'ok', elapsedMs, model }` or `{ outcome: 'failed', elapsedMs, errorKind, message }`.
- **Settings ▸ Models**: lists entries with what each runs ("Runs Claude Code with your login", "Via Claude Code (Agent SDK)", or the model and base URL), whether a key is set and a warning for a server off this machine; Add (kind, then a form), Edit, Remove, Test; Fetch Models for an OpenAI-compatible server; a write-only key field (placeholder "Set — type to replace", Save/Replace Key, Remove Key); and one select per role. Accounts keeps GitHub and Claude Code's status. The copy says what runs; nothing suggests who made beuve.
- **`--bare`**: `claude --help` (2.1.314, checked 2026-10-30) has `--bare` ("Anthropic auth is strictly ANTHROPIC_API_KEY or apiKeyHelper … OAuth and keychain are never read") but no flag to opt out of it, and `claude auth status` reports the login without a model call. Should `--print` default to bare, a login would be ignored. The CLI adapter therefore reads the init event's `apiKeySource`: a run on the user's login reports `none` (captured fixture); any other source (an API key or helper) is stopped at once as `not-authenticated` ("Claude Code did not use your Claude Code login (credential source: …)"), before the model answers, and a run with no credential at all already ends with Claude Code's `/login` error, which maps to `not-authenticated`. When Claude Code adds an opt-out flag, add it to `buildClaudeCodeArgs`.

## Consequences

- A model is added, tested and assigned from Settings without code. A local model without tools answers from the diff and the selections; its answers and verdicts are weaker than an agent that reads callers, and the prompts say what it can't see.
- `/review` may verify findings on a different model family than the first pass, which lowers the shared-blind-spot risk ADR 0055 noted, at the price of a model that cannot read the code when it has no tools.
- Selections moved after the diff, so the diff message is identical across questions at one head; models that weigh the start of a prompt more may attend less to them. The question still names them.
- The packaged app grows by the Claude Code binary for Bundled. Linux `out/linux-unpacked` (`du -sb`, this container): 312 MB without it, 606 MB with it (the binary is 294 MB); the macOS dmg grows by the darwin-arm64 binary, to be measured on the first signed build.
- Settings writes `models` into `settings.json`; an older beuve ignores it. Removing an entry removes its key.

## Amendment 2026-10-31 (ADR 0087)

`ModelCapabilities.checkout` says whether an adapter reads `cwd` itself: `true` for the Claude Code CLI and the Agent SDK, `false` for the OpenAI-compatible adapter. `BaseModelRequest.cwd` is optional, and `tree` carries the reviewed commit's files from git objects. Chat leases a checkout only for a request whose models need one.
