# 0015. ImpactGate metrics, and the seam between syntax and impact

- Status: Superseded by [0102](0102-drop-impactgate-and-credit-its-sources.md)
- Date: 2026-10-28

## Context

ImpactGate (spec 5G) scores how a change moves the complexity of the functions it touches and flags those over a cognitive complexity limit. It needs syntax trees, but ADR 0002 forbids `src/internal/impact/` from importing `src/internal/syntax/` (ADR 0014). The metrics also need precise definitions, because reviewers will compare them with Sonar and Lizard output.

## Decision

- **Seam.** `impact` declares the node shape it reads, `ImpactNode` (`id`, `type`, `isNamed`, `text`, `hasError`, `startPosition`, `endPosition`, `children`, `childForFieldName`). Tree-sitter nodes satisfy it structurally. `runImpactCheck(files, parse, config)` takes a `ParseSource` callback whose signature the syntax domain's `SyntaxParser.parse` satisfies, so main passes `parser.parse` straight through. Each tree is measured inside the callback and dropped, so at most one tree is alive per file side. `measureFunctions` (tree to plain data) and `assessImpact` (measurements to report) are pure and exported separately.
- **Rule tables.** `LanguageRules` lists, by node type and field name, the functions, the naming scopes, the parents that name anonymous functions, the control-flow constructs (`branch`, `else`, `case`, `logical`, `jump`, `call`) and the nodes that boolean sequences pass through. `ecmascriptRules` covers the TypeScript, TSX and JavaScript grammars, and `rulesByLanguage` maps syntax language ids to tables. A test checks that every type and field a table names exists in the grammars. Tests parse real source through a test-only helper in `impact/testing/` that loads web-tree-sitter directly (ADR 0013), never the syntax domain.
- **Metrics**, per function, computed in one iterative pass:
  - _Cognitive complexity_ follows G. Ann Campbell's SonarSource whitepaper: +1 plus the nesting level for `if`, `switch`, `for`, `for…in/of`, `while`, `do`, `catch` and `?:`; +1 without a nesting increment for `else` and `else if`; +1 per run of like operators in a boolean sequence (`&&`, `||`, `??`, flattened through parentheses); +1 for `break`/`continue` to a label; +1 once for direct recursion (by name, or `this.name()` in methods). `try` and `finally` add nothing. The whitepaper's `sumOfPrimes` scores 7 and `getWords` (a switch) 1.
  - _Cyclomatic complexity_ is 1 plus each `if` and `else if`, loop, `catch`, `?:`, non-default `case`, and each `&&`, `||` and `??`.
  - _Length_ is the span in source lines. _Max nesting_ is the deepest control structure (1 for a single `if`). _Parameters_ are counted from the parameter list.
  - **Deviation from Sonar:** a nested function or callback is its own entry and starts at nesting 0, and its complexity is not added to the enclosing function. A `describe` block or a component full of handlers is then judged on its own flow, and each callback is visible on its own.
- **Names and matching.** Qualified names join classes, namespaces, object literals and enclosing functions with `.`. Anonymous functions take the name of the variable, property, field or `export default` they are assigned to. A callback is named after its call and first string argument (`describe('x').it('y')`), or `<anonymous>`. Get and set accessors are prefixed (`get value`). Repeated names get `#2`, `#3` in source order. TypeScript overload signatures have no body and are skipped, so overloads collapse into their implementation. Base and head functions pair by exact qualified name. Any left over pair as `renamed` when their whitespace-normalized bodies are identical and at least 32 characters long. Everything else is `added` or `removed`. A pair is `modified` when its normalized text differs.
- **Impact.** The input is plain data that main assembles from the git domain: per file, `path`, optional `previousPath`, base and head text (`undefined` for a missing side) and changed line ranges (removed lines by base number, added lines by head number). Each function entry carries its base and head snapshots, the delta (head minus base), and `inDiff` when its lines intersect the diff. Unchanged functions appear only when the diff touches them, for example when one moved. `percentile` is the mid-rank of the head cognitive value among all head functions of the analyzed files. That population is chosen over repository-wide because it costs no extra git reads or parses, and it compares a change with its own surroundings. A repository-wide baseline can later be computed once per head commit and passed in. A **finding** is an added, modified or renamed function whose head cognitive complexity exceeds `cognitiveMax` (default 15, Sonar's default). Its `trend` is `introduced`, `worsened`, `unchanged` or `improved`, compared with the base. Files without rules, oversized files and files that fail to parse are reported as `skipped` with a reason, and never fail the check. The whole report is JSON- and structured-clone-safe.

## Consequences

ImpactGate is deterministic and has no state, and it never touches the parser or git, so it is cheap to test and to call from IPC and MCP alike. Adding a language needs a grammar entry (ADR 0014) and a rule table, not new traversal code. Limits we accept: renames whose body also changed show as `removed` plus `added`. Ordinal names (`#2`) and `<anonymous>` callbacks can shift when an earlier sibling is added or removed. An outer function reads as `modified` with a zero delta when only a nested function changed. Recursion through other functions (mutual recursion) is not detected. Module-level code outside any function is not measured. Comment-only edits count as modifications. A function's line span includes its nested functions.
