# 0067. Sheets: whole files pinned to a commit, definition jumps and permalinks

- Status: Accepted
- Date: 2026-10-30

## Context

Reviewers asked to jump from a line of the diff to the definition of what it uses and read that whole file, "like pieces of paper" laid out beside the review to cross-reference. The diff stream shows hunks, not files; the call-hierarchy peek (spec 5D) shows names, not code. The LSP client lost `textDocument/definition` when unused code was removed. A file view must stay authoring-resistant (spec 1), keep the ADR 0005 security baseline, and not grow into an editor. Reviewers also wanted to hand the lines they are looking at to someone else as a GitHub link.

## Decision

- **A sheet is a snapshot.** It shows one file as it is at one commit (its blob at that sha), like a printout of a draft at a given stage: read-only, highlighted with the Alabaster themes (ADR 0025) through `@pierre/diffs`' `File` (`beuve-sheet-code`, the third allowed importer of `@pierre/*`), with line numbers, the change's marks in the gutter against the review base (the session base's fork point for that commit: green bar added, blue modified, red wedge where lines were removed; `sheetMarksFrom`), the session's staged notes as violet dots when the commit is the session head, find in the file (⌘F; Enter, Shift+Enter, `n`, `Shift+n`; smart case), a line cursor (`j`/`k`, `g`/`Shift+g`, clicking a line) and back/forward (`[`/`]`, ⌘[/⌘], Alt+←/→) over the places it showed. The header says `path:line · abc1234` and when it was printed; the window title says the same. Sheets are never refreshed and never reused: every open makes a new one, there is no limit, and when the session head moves on a sheet only notes it quietly in its footer (checked when the window gains focus with `sheet:get-head`).
- **Definitions.** `lsp:definition { sessionId, sha?, path, line, character?, kind? }` asks the language server, read-only, for `textDocument/definition` or `textDocument/typeDefinition` (both re-added to the multiplexer, with location links answered by their selection range). Without a column, main picks the token (`planDefinitionProbes`): the line's calls first, then its other names left to right, names the line declares last, outside strings and comments, at most six; it asks for each until a definition lies somewhere other than the token itself. An answer that lands on an `import` in the same file (typescript-language-server does this while a project loads) is followed once more, at the import and then through the module specifier and that module's symbols. With no token, the enclosing symbol's name is the answer. A definition inside the repository opens; one outside it (library typings) is named in the status bar.
- **At the sheet's own commit.** A jump from a sheet resolves against that sheet's commit, never "the head now": main checks the sha is a full commit of the session's repository, and the language server runs in a checkout of it from the worktree manager (ADR 0020), held under its own key (`sheet\0<session>\0<sha>`) so the session's head checkout is left alone. A checkout of an older commit lives until the next startup prune. A jump inside a sheet shows the target in the same sheet and joins its history; jumps from the main window open a new sheet.
- **Keys.** In the diff, `Shift+d` opens the definition of the target line's symbol (ADR 0063's `lineFromTarget`; the token is main's choice) and `Shift+t` its type; in a sheet the same keys, or ⌘-click on a word, follow the word under the cursor. Each call-hierarchy peek node has an "Open" button that opens its declaration (`beuve-sheet-request`). `/sheets window|inline` (a display preference in `settings.json`, `sheets`, default `window`) chooses between a sheet window per jump and one sheet over the diff in the main window (Esc closes it).
- **Windows.** `sheet:open` validates the request in main (session, full sha, a normal repository-relative path, the file being text at that commit) and opens a small `BrowserWindow` with the main window's `webPreferences` (context isolation, sandbox, no Node, web security, no webview, no drag-navigation), no menu bar, the strict CSP of `src/ui/sheet.html` (the same policy as `index.html`), and navigation, redirects and `window.open` denied by `hardenWebContents`. Its own preload, `sheet-preload.cjs`, exposes only `invoke` and only the sheet channels (`sheetInvokeChannels`: `lsp:definition`, `sheet:open`, `sheet:get-file`, `sheet:get-head`, `remote:permalink`, `remote:open-permalink`, `clipboard:write-text`), and `registerIpcHandlers` enforces the same list per page URL (`TrustedPage`), so a compromised sheet can't stage, export, post or open anything else. The snapshot travels in the page's query string. Each new sheet opens where the reviewer last left one of that session's sheets (in memory), stepped by 28 px per open sheet (`planSheetBounds`); Esc or ⌘W closes it. The sheet page is a second entry of the ui build (`sheet-entry.js`, sharing its chunks); no file is loaded by path beyond `dist/`.
- **Permalinks.** `remote:permalink { sessionId, sha, path, startLine?, endLine? }` builds `https://<host>/<owner>/<repo>/blob/<sha>/<path>#L<a>-L<b>` (`permalinkFrom`: owner, repository and each path segment percent-encoded, `#L<a>` for one line, no anchor for the whole file; GitHub Enterprise Server hosts as written) on the primary remote (`choosePrimaryRemote`: the remote naming a pull request's base repository, else `origin`, else the first GitHub remote), or answers `no-remote`. Whether the remote has the commit is not checked: an unpushed commit's link answers 404 until it is pushed. `remote:open-permalink` builds the same link in main and opens it with `shell.openExternal`, so it is always https to the repository's own remote host and the renderer never names a URL. `Shift+y` copies and `Shift+o` opens a link to the diff target (ADR 0063: a selection on its own side, a hunk's head lines, a jump's line, else the whole file; base side for a deleted file); every sheet has "Copy link" and "Open on GitHub" (and the same keys) for its own commit, path and cursor lines.

## Consequences

Reviewers can lay several drafts of a file side by side and follow definitions through them without leaving the review, and a sheet means the same thing tomorrow as when it was printed. Nothing in a sheet can change a file. A sheet at an older commit costs a checkout until the next start, and its first jump waits for a language server to load that checkout. The marks follow the file's path, so a renamed file shows as added. Line-level highlighting stands in for the exact token range. Permalinks to unpushed commits are dead until pushed, which the reviewer accepts in return for links that never move. Sheet windows add a page, a preload and six channels to the security review surface; adding a channel to sheets means adding it to `sheetInvokeChannels` deliberately.
