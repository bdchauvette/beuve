# 0022. Opt-in preliminary review, run from a chat command

- Status: Superseded by [0055](0055-review-folded-into-chat-with-verification.md) (opt-in from the chat, the grammar and how `claude` is found still hold); run keying, attach rules and `--fresh` statuses amended by [0024](0024-review-runs-keyed-by-path-scope.md); promotion stages a URA item since [0027](0027-ura-dock-keyboard-clipboard-and-outdated-items.md)
- Date: 2026-10-28

## Context

Spec 5B runs the preliminary agentic review automatically on session load. ADR 0019 built the review domain and a Claude Code CLI adapter, but every run sends the diff, the ImpactGate findings and whatever worktree files the model reads to Anthropic through the user's own Claude Code account, and spends that account's quota. The user decided that this must be opt-in, started by a command in the Zone 4 chat drawer. The drawer stays read-only (spec 1): nothing typed there can change the worktree. Q&A comes later and will grow from the same input.

## Decision

- **Trigger**: no run on session load. The reviewer types a command in the chat drawer, the only place a run starts. `c` opens the drawer or focuses its input (pressed in the drawer, it closes it), Enter submits, and Escape returns focus to the diff stream. The transcript is in memory; `chat_messages` persistence comes with Q&A. The empty drawer and `/help` say what leaves the machine.
- **Grammar** (`src/ui/parse-chat-command.ts`, pure): `/review [--fresh] [--effort=low|medium|high] [path-prefix…]` (`--effort low` works too; `--` ends the options), plus `/help` (or `/?`). A prefix matches that path and everything below it, on either side of a rename. It is repository-relative and normalized by `#contract/normalize-path-prefix.ts`, which the parser and main's zod validation share. Unknown commands, malformed options and plain text (until Q&A exists) get a message in the transcript, never an error.
- **Channels**: `review:run { sessionId, pathPrefixes?, fresh?, effort? }` answers at once with `{ status: 'started' | 'attached' | 'reused', runId, sessionId, headSha }` (`reused` carries the stored summary). Before answering, main refreshes the head (a few git spawns), because a run is keyed by (session, head). The push channel `review:progress` sends `started`, `progress` (coarse text: stage, model, tool-call count, never content), then `completed` (counts, drop reasons, model, files, duration) or `failed` with a typed code: `not-installed`, `not-authenticated`, `rate-limited`, `timeout`, `cancelled` (`head-changed | superseded | app-quit`), `nothing-to-review`, `review-unavailable`, `model-failed`. `review:list-insights { sessionId }` lists the current head's insights, its stored run and any in-flight run id. `review:set-insight-status { insightId, status }` takes `pending | promoted | dismissed`. `promoted` is only a status until the URA domain exists.
- **Lifecycle** (`src/main/review/create-review-services.ts`, following ADR 0019's recipe): one run per (session, head, path scope; ADR 0024). A stored run is reused unless `--fresh`. A request while a same-scope run is in flight attaches to it. `--fresh` aborts an in-flight run (`superseded`) and replaces the stored run, insight statuses included, in one transaction (`replaceReviewRun`). A run builds the same diff as `session:get-review` (an interdiff fallback is reviewed as `full`), adds the cached ImpactGate findings, checks out the head (ADR 0020), runs `runPreliminaryReview` with `createClaudeCodeModel` in that checkout, and stores the result with `insertReviewRun`. Every session refresh that stores a new head (`SessionContext.onHeadMoved`) aborts that session's run for the old head; quitting aborts all runs and waits for their process groups to go away.
- **Finding `claude`**: resolved for every run, because GUI apps on macOS inherit a minimal `PATH`. The order is `BEUVE_CLAUDE_PATH` (absolute or `~/…`; if it doesn't name an executable, the run fails as `not-installed` instead of falling back), then `~/.claude/local/claude`, `~/.local/bin/claude`, `/opt/homebrew/bin/claude`, `/usr/local/bin/claude`, then each absolute `PATH` entry. The resolved directory is put first on the child's `PATH`, so an npm-installed `claude` finds the `node` next to it.
- **UI**: insights render as purple "Agent insight" blocks after the last shown head line of their range in the `<pre>` file cards (`place-insights.ts`). Ranges the patch doesn't show are listed above the diff. A block shows severity, category, lines, confidence, the title, and a tiny Markdown subset of the body, rendered as text nodes (`parse-insight-markdown.ts`); model output never reaches `innerHTML`. With the diff stream focused, `]`/`[` move between insights (`n`/`N` are left free for search), `y` promotes and `d` dismisses (each again to undo), and a dismissed insight collapses to a one-line stub. The transcript shows "4 insights, 2 dropped (out of diff)" with citation pills that jump the diff stream to each insight. `beuve-agent-insight` is self-contained, so `@pierre/diffs` annotations (ADR 0018) can reuse it with the same data.

## Consequences

- **Privacy**: nothing leaves the machine until the reviewer types `/review`, and the drawer says what is sent: the diff, the ImpactGate findings and any worktree files Claude Code reads (`--restricted` keeps reads in the checkout). It goes to Anthropic under the user's Claude Code account's terms and data settings. beuve never sees a credential, and no prompt or file content is logged or pushed in progress events.
- Superseded by ADR 0024: runs are stored per (head, path scope), a request attaches only to a run with the same scope, and `--fresh` keeps the old insights' statuses.
- Refreshing the head before `review:run` answers costs a few git spawns. In exchange, attach and reuse are decided against the right head.
- Tests drive the review domain's fake `claude` (`review` mode), never the real CLI. A logged-out or rate-limited real CLI is mapped from texts that aren't a documented interface (ADR 0019).

## Amendment 2026-10-30: superseded by ADR 0055

`/review` is now a chat request whose answer lists the findings in the transcript; `review:*` channels, `review:progress`, the insight blocks in the file cards and the `]`/`[`/`y`/`d` keys are gone. Still true: nothing runs until the reviewer types `/review`, the drawer says what leaves the machine, the `/review` grammar (now with `--no-verify`), and the order in which `claude` is looked up (code in `src/main/chat/resolve-claude-command.ts`).
