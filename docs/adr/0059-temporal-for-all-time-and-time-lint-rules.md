# 0059. Temporal for all dates, times and durations; two lint rules keep it that way

- Status: Accepted
- Date: 2026-10-30

## Context

Time was read three ways: injected clocks (`SessionDeps.now`, `UraDeps.now`, `LoggerOptions.now`, `createTraceTrust({ now })`, `createGithubClient({ now })`, `createCachedCredentialProvider({ now })`, `reviewChange({ now })`, `ServerSession({ now })`), `Date.now()`/`new Date()`, and `performance.now()`. Durations were millisecond numbers combined by hand (`Date.parse(resetAt) - now.getTime() + 1000`, `now - started >= quietMs`). Injected clocks exist only so tests can pin time, and every new consumer has to thread one through. `Temporal` is native everywhere beuve runs (ADR 0060), and Vitest 5 fakes it.

## Decision

- **Read time directly.** Code calls `Temporal.Now.instant()` (or `Temporal.Now.plainDateISO('UTC')`, …). No clock is injected; the `now` fields and options above are gone. A value that _is_ data stays a parameter, typed with Temporal: `classifyGithubResponse(head, body, receivedAt)`, `savePullRequest(…, fetchedAt)`, the URA transitions' `now: Temporal.Instant`, `formatRelativeTime(iso, now)` (one render's reference point) and `nextCalverVersion(tags, date: Temporal.PlainDate)`.
- **Stored and IPC form.** Timestamps in SQLite and over IPC stay ISO-8601 strings in exactly the old `Date#toISOString()` shape, written with `instant.toString({ fractionalSecondDigits: 3 })`, so rows still sort as strings. `isIsoTimestamp` validates that shape with `Temporal.Instant.from`.
- **Durations.** Time math uses `instant.add/since/until`, `Temporal.Duration` and `Temporal.{Instant,Duration}.compare`. Elapsed times for logs are `Temporal.Now.instant().since(started, { smallestUnit: 'millisecond', roundingMode: 'halfExpand' }).total('milliseconds')`. Options that take milliseconds (`timeoutMs`, `intervalMs`, `ttlMs`, …) stay numbers at API boundaries for now and become a `Temporal.Duration` (`Temporal.Duration.from({ milliseconds })`) where the code computes with them. File stamps read `stat(…, { bigint: true })` and `Temporal.Instant.fromEpochNanoseconds(stats.mtimeNs)`.
- **Boundaries.** A `Date` from another API is converted at once with `date.toTemporalInstant()` (TypeScript's `lib.esnext.date`). A raw millisecond number from outside (epoch seconds in a header, `fs.Stats#mtimeMs`) goes straight into `Temporal.Instant.fromEpochMilliseconds`. A Temporal value leaves as a number only into an API that wants one: `setTimeout(fn, duration.total('milliseconds'))` (it truncates fractions). There are no wrapper helpers for these.
- **`local/no-date`** (type-aware) reports the global `Date` (`new Date()`, `Date()`, `Date.now/parse/UTC/…`, `instanceof Date`, `Date.prototype`), `Date` in type positions, and any use of a `Date`-typed value except `.toTemporalInstant()`. Options: `allowMembers` (further members readable on a Date) and `allowGlobalUses` (`'instanceof'`, `'prototype'`). Only `create-trace-recorder.ts`, which renders arbitrary values from the program under test, allows `instanceof` and `prototype`.
- **`local/no-time-number-arithmetic`** (type-aware) tracks numbers read from Temporal escape hatches (`epochMilliseconds`, `epochNanoseconds`, `offsetNanoseconds`, a `Duration` unit field, `duration.total(unit)`) and from `sources` (default `performance.now`, `Date.now`), through local `const`/`let` bindings in the same function. Such a number may be bound, returned, or passed unchanged to a sink: a call in `sinks` (default `setTimeout`, `setInterval`, `AbortSignal.timeout`, `Temporal.Instant.fromEpochMilliseconds`, `Temporal.Instant.fromEpochNanoseconds`, `String`) or the value of a key in `sinkProperties` (default `timeout`; beuve adds `durationMs`, `computeMs` and `timeoutMs`, its log fields and the millisecond options internal APIs still take). Arithmetic, comparison, `++`/`--`, compound assignment and `Math.*` on it are reported, with a dedicated message when the other operand is a unit constant (`1000`, `60`, `3600`, `86400`, `60 * 60 * 1000`, a `const` set to one, …); so is passing it to any other call or storing it under any other key. Messages name the Temporal API to use instead.
- Both rules apply to `src/**` and `scripts/**` except unconverted tests, and to converted tests (ADR 0058).
- **Tests control time with Vitest's fake timers**, never with an injected clock: `vi.useFakeTimers({ toFake: ['Date', 'Temporal'], now })` pins `Temporal.Now` and `Date` and leaves timers real (Vitest 5 added `'Temporal'` to `toFake`; the default `toFake` list fakes it too when present, and `vi.setSystemTime` alone fakes `Date` and `Temporal`). Converted tests use the `clock` fixture (ADR 0058). Fake time is global to the file, so such a test is declared `{ concurrent: false }`.

## Consequences

Nothing threads a clock any more, and a new consumer of time needs no plumbing. Tests that check exact timestamps run one at a time, which costs little because only a few do. `Temporal.Now.instant()` is wall-clock time, unlike `performance.now()`, so a clock step (NTP, sleep) can stretch or shrink a measured duration, a diagnostics wait or the LSP crash window once; beuve accepts that for log durations and coarse timeouts. Millisecond options remained at API boundaries at the time of writing; the 2026-10-30 amendment below moves them to `Temporal.Duration`.

## Amendment 2026-10-30: monotonic stopwatch, Duration-typed APIs, IPC edge

- **Elapsed time is measured with `new Stopwatch(options?)`** (`src/x/time/stopwatch.ts`), which starts on construction; its `elapsed()` is a `Temporal.Duration` balanced up to seconds (`round({ largestUnit: 'second' })`). The options bag takes `now?: () => bigint`, monotonic nanoseconds; the default is `process.hrtime.bigint` where it exists (main process, workers, tests) and a `performance.now()`-based nanosecond bigint otherwise (renderer). The Duration is built from whole nanoseconds. A monotonic clock cannot be stretched by an NTP step or a sleep, which was the Consequences caveat above. `Temporal.Now.instant()` stays for wall-clock facts: timestamps stored or sent, cache expiry, a rate limit's `resetAt`. Log durations, subprocess and request timing, the diagnostics wait, the restart window, the idle clock, the poll interval and the review's shared time budget now use stopwatches.
- **`local/no-time-number-arithmetic` bans `performance.now`, `process.hrtime` and `process.hrtime.bigint` everywhere** (the rule has no path exception; `src/x/time/stopwatch.ts` opts out with a file-level `eslint-disable local/no-time-number-arithmetic` comment giving the reason), with a message pointing at `new Stopwatch()`. `performance.now` and `Date.now` remain default sources, so arithmetic on them is reported too. The `sinkProperties` allowances `durationMs`, `computeMs` and `timeoutMs` are gone; only the default `timeout` key remains.
- **Our own APIs take `Temporal.Duration`** for every timeout, interval, grace, TTL and measured duration, named without a unit suffix: `timeout`, `killGrace`, `interval`, `ttl`, `idleTimeout`, `requestTimeout`, `diagnosticsQuiet`, `duration`, `compute`, … Defaults are written `Temporal.Duration.from({ seconds: 30 })`. A Duration becomes a number only at a sink the rule allows (`setTimeout`, `setInterval`, `AbortSignal.timeout`, the child-process `timeout` option) via `duration.total('milliseconds')`. Foreign numbers are converted on entry (`Temporal.Duration.from({ milliseconds: Math.round(report.duration) })` for Vitest's report). Durations in error values are Durations too; messages round with `duration.round({ largestUnit: 'second', smallestUnit: 'second' })`. `multiplyDuration` (`src/x/time/multiply-duration.ts`) covers the one need for a whole-number multiple.
- **IPC edge.** Temporal objects do not survive structured clone (`DataCloneError`), so the contract carries durations as ISO-8601 duration strings (`ImpactView.compute`, `TraceResultView.duration`, `TraceTimelineView.duration`, e.g. `PT0.712S`), the same choice as ISO-8601 timestamps. Main converts with `duration.toString({ smallestUnit: 'millisecond' })`; the UI parses with `Temporal.Duration.from` (`formatDuration` takes the string). The agent-facing MCP output uses the same strings.
- **Testing elapsed-time logic.** Fake timers and the `clock` fixture fake `Date` and `Temporal.Now` only; they do not move `process.hrtime`, so the default stopwatch is never faked. A test of `Stopwatch` itself, or of code that takes one, controls elapsed time by passing a fake `now` (`new Stopwatch({ now: () => fake.nanoseconds })`). Production code that builds its own stopwatch is tested with real, short durations and margins (a zero or tiny budget for the "already spent" branch, a bound with a few seconds of slack, a few milliseconds of real waiting for idle time), or is written as a function of the measured Duration so the test passes the value in. `clock` remains the tool for wall-clock facts.
