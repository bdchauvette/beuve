# 0019. Review model port, and Claude Code CLI as the first adapter

- Status: Partly superseded by [0055](0055-review-folded-into-chat-with-verification.md): the adapter decisions stand (moved to the llm domain by [0030](0030-llm-domain-and-structural-model-ports.md)); the review domain, its persistence and `runPreliminaryReview` are gone
- Date: 2026-10-28

## Context

The preliminary agentic review (spec 5B) needs an LLM that can read the worktree around a diff and return line-anchored insights. We don't want the `review` domain tied to one vendor or transport, and we don't want beuve to handle model credentials. The Agent SDK documentation states: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK. Use the API key authentication methods described in the Quickstart instead." Users who review with beuve typically already have Claude Code installed and logged in (often on a Team plan). beuve is authoring-resistant (spec 1): the reviewer may read the worktree, never change it.

## Decision

- **Port** (`review-model.ts`): `ReviewModel.run(request) → Promise<Result<ModelOutput<T>, ModelError>>`, never rejecting. The request is `{ system, prompt, cwd, outputSchema, timeoutMs, signal?, onProgress? }`; `outputSchema` is a zod schema that adapters send as JSON Schema and validate replies against. `ModelError` is `invalid-request | not-installed | not-authenticated | rate-limited | timeout | cancelled | output-too-large | invalid-output | model-failed | process-failed`. An Agent SDK or Claude API adapter (API key, Bedrock, Vertex) fits the same port later.
- **First adapter: the user's installed `claude` CLI, headless** (`create-claude-code-model.ts`). Claude Code authenticates with the user's own login; beuve never sees or stores a credential. Flags, each checked against `claude --help` for 2.1.312: `--print`, `--output-format=stream-json` with `--verbose` (verified: stream-json fails without it), `--input-format=text`, `--no-session-persistence`, `--safe-mode` (no CLAUDE.md, skills, plugins, hooks or MCP servers from the untrusted worktree), `--restricted` (no code-running tools, file tools confined to the working directory, settings files ignored), `--strict-mcp-config` with no `--mcp-config`, `--disable-slash-commands`, `--permission-mode=dontAsk`, `--permission-prompts=none`, `--tools=Read,Grep,Glob`, the same `--allowed-tools`, `--disallowed-tools=Bash,Edit,Write,NotebookEdit,WebFetch,WebSearch`, `--append-system-prompt`, `--json-schema`, and optionally `--model`, `--effort` and `--max-budget-usd`. Values use `--flag=value`, because the tool flags are variadic and would swallow the next argument. A real run confirmed the tool set (`Glob`, `Grep`, `Read`, `StructuredOutput`), no MCP servers, and the answer in the result event's `structured_output`.
- **Not available or not used**: there is no `--max-turns` or `--cwd` in 2.1.312, so turns are bounded by the timeout (and `--max-budget-usd` if set), and the working directory is the process's `cwd`. `--bare` is not used: it accepts only `ANTHROPIC_API_KEY` or an `apiKeyHelper`, which would bypass the user's login.
- **Process handling**: `spawn` without a shell; `cwd` is the worktree; an allow-listed environment (`PATH`, `HOME`, `USER`, temp, locale, `CLAUDE_CONFIG_DIR`, `XDG_CONFIG_HOME`, proxy and CA variables; never API keys, `CLAUDE_CODE_*`, `NODE_OPTIONS`, `ELECTRON_*` or tokens), plus anything main passes explicitly. The prompt is written to stdin, since Linux caps a single argv string at 128 KiB. The CLI runs in its own process group; a timeout or abort sends SIGTERM to the group, then SIGKILL after a grace period. Stdout is capped at 32 MiB, and stderr keeps a 4 KiB tail. Exit codes and error results are mapped to `ModelError`: 401/403 or the `/login` hint become `not-authenticated`; 429/529, a rejected `rate_limit_event` or usage-limit text become `rate-limited`; other `error_*` subtypes become `model-failed`. These texts aren't a documented interface and the logged-out case couldn't be reproduced here, so unknown failures fall back to `model-failed` or `process-failed` with the message kept. Prompt contents are never logged; info logs carry only duration, model, turns and cost.
- **Domain**: `buildReviewPrompt` is pure and deterministic, with a character budget (300k in total, 60k per file, 8k for the intent). A file that doesn't fit whole keeps its leading hunks. Every omission (hunks, files, binary files, intent text, ImpactGate findings) is named in the prompt with a pointer to read it from the worktree, and listed in a `PromptReport`. Untrusted text is fenced so it can't close its own fence. `validateInsights` drops insights on unknown, deleted or binary files and outside every hunk. It narrows ranges to the hunks they touch, dedupes, drops confidence below 0.3, and keeps the 12 most severe and confident, reporting counts per reason. `runPreliminaryReview` is pure apart from the port, the clock and the ids.
- **Persistence** (ADR 0006, `review-migrations.ts`): `review_runs` (unique per session and head; scope, fork point, previous head for interdiffs, model, counts) and `agent_insights`. `agent_insights` adapts the spec's `agent_comments`: it has a `run_id`, a head-side `line_start`/`line_end` instead of `line_number`, `title`, `confidence`, status `pending | promoted | dismissed` instead of `pending_review`, and CHECKs on every enum, range and format. Both tables cascade from `sessions`, so main runs `sessionMigrations` first.

## Consequences

- **Privacy**: the diff, the stated intent, ImpactGate findings and any worktree file the model reads are sent to Anthropic through the user's own Claude Code account, under that account's terms and data settings. `--restricted` keeps reads inside the worktree. Main should make the review opt-in per repository and say so in the UI.
- beuve depends on a CLI it doesn't ship. Flags may change between versions; the argv builder is one pure, tested function, and the stream parser ignores unknown events.
- macOS GUI apps get a minimal `PATH`, so main should resolve `claude` (or let the user set its path) and pass it as `command`.
- Each run costs a process start of about a second, plus the model's time. Quality depends on the model following the schema, which Claude Code enforces through its structured-output tool, and on the rules in the prompt. Validation keeps output anchored to the diff, but it can't judge whether an insight is right.

## Amendment 2026-10-30: the review domain is folded into the chat

ADR 0055 makes `/review` a chat request. The port, the Claude Code adapter, its flags, process handling and error mapping are unchanged. The `review` domain, `review_runs` and `agent_insights` are removed. `buildReviewPrompt` gives way to the chat's prompt builder with a review task (same budget rules, shared fencing), `validateInsights` lives on as the chat domain's `validateFindings` (same rules), and insights are now findings stored with their answer.
