# 0037. GitHub pull request sessions: local clones, fetch-and-verify, and stored metadata

- Status: Accepted
- Date: 2026-10-28

## Context

ADR 0034 and 0035 built the credential provider and the REST client but nothing reached them. Opening a pull request needs answers that constrain later work: where its commits come from (beuve computes diffs locally, ADR 0010), which repository on disk it belongs to, how a force-push racing the fetch is handled, what identifies the session so it can be resumed (GitHub Enterprise included), and where the title, body and state live so the intent survives a restart without a network call.

## Decision

- **Channel** `github:open-pr { ref, repoPath? }`: `ref` is anything `parsePullRequestRef` accepts. Expected failures are a typed `{ kind: 'failed', failure, message, remedy? }` (`invalid-ref`, `not-signed-in` with `gh auth login --hostname <host>`, `not-found`, `forbidden`, `rate-limited`, `needs-local-clone`, `fetch-failed`, `head-mismatch`, `github-failed`), not an `IpcError`.
- **Local-clone policy**: beuve never clones. It uses `repoPath`, else the clone last used for that repository (`githubClonePaths` in `<userData>/settings.json`, keyed by lowercase `host/owner/repo`, written on every successful open), and the clone must have a remote whose configured URL names the pull request's base repository (https, ssh, scp-like and `ssh.github.com` forms; case-insensitive). Otherwise the answer is `needs-local-clone`, asking for a path. Remote URLs are read with `git config --get-regexp '^remote\..+\.url$'`, not `git remote -v`, because the URL the user wrote, before `insteadOf` rewrites, is what names the GitHub repository. Fetching goes through that remote and the user's credential helper (ADR 0035's first option); tokens never reach git.
- **git `fetchRefs(repo, remote, refspecs)`**: no shell, `--no-tags --no-write-fetch-head --no-recurse-submodules --no-auto-gc --refmap= --end-of-options`, a 2-minute timeout, refspecs validated as `[+]refs/<src>:refs/<dst>` with a conservative ref-name subset, and destinations only under `refs/beuve/`, so a fetch never moves the user's branches or (thanks to `--refmap=`) their remote-tracking refs.
- **Fetch and verify**: `refs/pull/<n>/head` into `refs/beuve/pr/<n>/head` and the base branch into `refs/beuve/pr/<n>/base`, then the fetched head must equal the `head.sha` GitHub reported. A mismatch means a push raced us: the pull request is asked for again and fetched once more; a second mismatch is `head-mismatch` ("try again").
- **Session**: `github-pull-request` sources gain `host` (migration `session-0003-pull-request-host`, `ALTER TABLE` plus a backfill of `github.com`, because rebuilding `sessions` would cascade-delete every table that references it; the column CHECK allows a host only on pull request rows; the unique index becomes `(repo_path, host, owner, repo, pr_number)`). `owner/repo` is the base repository as GitHub names it now, so a renamed repository resolves to one session. `baseRef` is `refs/beuve/pr/<n>/base`, a constant, so a retargeted pull request stays the same session while its base tip follows the fetch. Opening again is idempotent through `findSessionBySource`; a moved head goes through `advanceHead` and main's `onHeadMoved` (runs aborted, URA re-anchored).
- **Metadata** lives in the github domain's `github_pull_requests` table (`github-0001-pull-requests`, run after the other domains), keyed by `(host, owner, repo, number)` rather than by session: two clones of one pull request share it, and the github domain depends on no other domain's table (ADR 0006). It holds title, body, author, state, draft, URL, branches and SHAs, GitHub's `updated_at` and when beuve fetched it. No tokens, ETags or CI results are stored. `session:list` adds each pull request session's title, state, draft flag and base branch; `github:get-pr { sessionId }` returns the stored metadata, stack and last CI status.
- **Intent**: the title and body are the session's intent: the intent section shows them, and the preliminary review gets them as its `intent` (ADR 0022). Chat has no intent input yet.

## Consequences

Opening a pull request costs one API call, one fetch and a ref check; a reviewer without a clone is told what to do instead of beuve cloning gigabytes on their behalf. A clone whose only remote is a fork can't open the upstream pull request until it gains a remote for the base repository. Metadata rows outlive their sessions (sessions are never deleted yet). The insteadOf-aware remote matching means a `url.<local mirror>.insteadOf` setup still works, which the tests rely on.
